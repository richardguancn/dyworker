# Cordis 与 DSH 兼容改造实施记录

更新日期：2026-10-07。继续执行 assessment.md 的两层路线，保留 Cordis 和 DYWorker 原有任务入口。现在已经实现第一层工具兼容，以及第二层的官方任务驱动、会话持久化、子任务、工作流、用户提问、压缩和配置表单。**全部目标仍在实施，不能将当前结果描述为任意 DSH 插件均兼容。** 首批记录另存为 implementation-first-batch.md；原 assessment.md 保留改造前的结论。

## 已实现和实际验证

第一层的工具、接口清理、停止、安装回退、依赖锁定、客户端模块加载和版本支持记录已经保留并通过回归。外部代码的兼容探测和工具执行在独立进程中运行，不传入已解密应用设置。停止/超时会等待进程实际结束；安装超时也会终止所属进程树并等待退出，不在子进程仍可能写入时宣告回滚完成。

第二层现在使用固定版本的官方 agent loop、工具、systemPrompt、会话、投影、持久化、压缩和子任务组件。每个根会话独立运行，不覆盖 DYWorker 的权威历史。官方会话重启后继续原事件，spawn/fork 子会话继承所属工作目录，压缩实际请求摘要模型并写入可重放记录。只读页面请求被取消时不会杀掉正在运行的任务；任务停止仍会终止该根会话进程。

DSH 缺少模型设置时现在明确失败，不进入原生演示模式，也不提前保存本轮显式记忆。服务地址、模型名称和远程密钥由共用入口检查；本机回环地址支持免密服务，真实模型请求不带空 Authorization。远程地址及伪装成 localhost 的远程域名仍要求密钥，安全存储不可用时仍拒绝保存非空密钥。实际运行检查覆盖缺项、空白、补齐后执行、真实免密请求，以及回环和远程地址边界。窗口重现失败返回与结束事件重复追加回复后，改为归并到本轮所属回复；两种先后顺序、已完成回复不被通讯错误覆盖及已有部分正文保留均已检查，失败不会落入已切换到的另一会话。

模型提供方由父进程保管。DSH 使用应用中选定的模型，插件拿不到模型密钥；模型请求和用量接回原有入口。办公插件的原始工具名不会误落入本应用的只读白名单，DSH 自身策略不能撤销父进程的拒绝，强制人工规则不由审核模型覆盖，改写审核策略文件也不会让审核模型自己批准。

已声明的应用/MCP 工具会带入官方任务。父进程许可绑定所属会话、调用编号、工具名和实际参数，并在调用时消费一次。真实测试验证模型收到工具定义、父进程收到正确参数、真实返回值进入后续模型请求；拒绝时调用次数不增加。完成声明现在沿用原生任务的实际证据检查：未写出的文件、没有调用上传动作或没有有效上传回执，不能显示为已完成。相关上传回执为隔离测试数据，没有真实向外发布。当前已补充图片和文件上传、模板与记忆写入、挂起唤醒和正式结束；下文列出已验证范围及剩余差异。

工作区 AGENTS.md、选中的记忆页、长期目标和当前工作记录已经进入官方上下文。原生工作模板保持原有编号，列表只披露已启用模板，完整执行要求通过批准后的 list_skills/load_skill 读取；停用模板不提供，未将工作模板读写能力冒充为官方 skills 服务。文字附件保留展开后的内容。上传的 PNG/JPEG/WebP/GIF 使用官方附件保存与校验，图片在父进程读回后进入实际模型请求；普通文件保留官方引用，read_attachment 只接受实际执行任务自己的消息中已保存的文件编号，经过完整校验后读取文字及办公文件。跨会话编号和改写过的文件被拒绝，重启后仍可读取；带图片历史的手动压缩也已实际运行。远程图片 URL、尚未接入的内容类型明确拒绝。普通文件提取仍可能依赖系统 Python、PDF 提取器或旧文档转换工具，不把包内 Node/npm 描述为所有文档处理依赖均已自带。

配置使用官方 ConfigEditor、Settings、SettingsDescribeMirror 和 ConfigForms，写入当前 DSH 会话自己的配置树。真实检查覆盖连续保存、版本冲突、未声明字段拒绝、两个会话独立、重启保留和插件启用后组合变化。浏览器组件现在会把插件注入的数据源转换为订阅钩子；菜单接回官方 onSelect 行为，原样 dsh-context 的设置项可以实际保存。

已启用的客户端界面在应用重启后自动加载，停用仍清理自身界面和样式。DSH 会话不再混用内置上下文页面的估算接口。首次选择 DSH 会话时，等会话存档完成再刷新配置，避免页面读取早于存档而一直不可用。

官方用户提问已接回桌面与收件箱，保留题目编号、说明、单选、多选和自由填写。取消或没有可用入口时明确返回失败；停止会解除等待，不影响其他会话。macOS 实际窗口选择 Word/PDF 并填写补充说明、随后填写第二题，已核对后续模型请求中的原始回答，见 ui-question-answer.json。

官方 PTC 程序执行由父进程托管，仍使用官方 Node 执行器和系统文件保护，并叠加 Node 权限。实际检查覆盖绑定函数回调、文件读写、越界拒绝、私有文件读取拒绝、禁止自行启动程序、超时和停止后没有迟到写入。官方前台/后台工作流已接通：子任务有真实记录，完成通知会回到根任务，job_output 能读取真实结果。应用保留根任务的执行资格直到所属后台工作及完成通知收尾；不能将此描述为根任务结束后仍可无限独立运行的后台模型任务。

工作模板的新建和修改先实际写入再返回成功，保留原编号，拒绝覆盖只读文件和修改停用模板；同一存储的写入按序处理。save_memory 写入真实记忆页，会话和工作区归属由父进程确定，插件不能替换。相关检查覆盖保存、读回、重启及拒绝操作。

sleep_until 只由根任务登记，检查已有唤醒和所属后台工作，停掉本轮运行并等待存档后才进入应用唤醒调度；停止或失败不登记唤醒。实际推进测试时间，重新打开历史，到点只恢复一次。finish_task 收束官方一轮后仍经过应用的产物证据检查，缺少文件或回执不能显示已完成；持续目标只有得到有效交付且明确声明完成时才结束。这些属于应用任务入口，没有冒充上游尚未实现的服务。

插件详情页现在展示真实状态、版本、来源、作者、许可证、包内说明和所需能力，支持检查当前版本、启停、卸载与重新加载界面。内置插件不提供卸载，未安装插件只显示市场资料与安装入口。说明中的图片不自动联网，HTML 不执行，只有符合限制的 HTTPS 地址可打开；包内说明限定大小和归属，不能借软链读取包外文件。

安装事务保留其他已登记插件及其运行和界面依赖，避免 npm 把手工预编译插件当成多余目录删除。缓存标记不再成为官方设置身份，旧设置文件会迁移到稳定名称；实际窗口重装办公插件后，上下文插件的“轮次”设置仍可读取，另一会话仍是“步骤”。重新加载先清理旧界面，普通官方状态与布局库在构建时适配，保持真实算法、组件和样式；同一文件被包名及 client 子路径引用时只登记一次。共享依赖的任意版本组合仍需逐个验证。

兼容检查现在分别检查工具运行方式和 DSH 会话运行方式。需要第二层能力的插件会在临时目录真实启动；只有成功才报告可用，并提示选择“DSH 插件会话”，不将尚未启动的会话插件显示为原生工具已启动。应用启动时修正仍指向旧安装目录的共享软链，不覆盖真实插件包。

DSH 实际请求、回复、用量、工具调用与结果现在写入原有轨迹记录，工具调用和结果按真实编号关联。运行说明按官方消息来源识别，不占据用户输入的位置，原始请求仍保留完整内容。不补造首字计时或办公插件的文件活动。DSH 会话读取原生插件接口时仍交给原生插件，避免将轨迹读取错送到官方插件会话。

跨会话上下文总览已经接入原样 dsh-context 的侧栏入口和全局浮层。各根会话使用自己的官方投影，存为父进程持有的摘要；冷存档逐个恢复，已有摘要不启动模型任务，临时读取进程用后关闭。列表携带真实工作区成员、当前任务和归档集合，卡片通过应用原有入口切换任务。完整消息和事件不进入总览，保留插件需要的最后提问预览；缺失统计不补估算。应用更新任务列表后会刷新总览；从总览的设置按钮可直接打开本插件详情。窗口关闭时遇到进程通讯断开，已补充启动后错误处理和关闭收尾，实际子进程的在途请求拒绝与停止检查通过。原样官方 Tooltip 保持图表列锚点，避免额外包装导致百分比高度失效，语义色也已接入。真实窗口展示 5 个历史任务和 19.4k 累计用量，搜索办公任务后点击进入对应历史；归档后总数变为 4，取消归档后恢复 5。未识别计价的隔离模型显示费用不可用，历史模拟回复产生的速度不代表真实外部模型速度。

原样 dsh-context 的 /context 命令已经接入真实输入框和 conversation.input.overlay。菜单、键盘选择及直接发送均只打开本任务弹窗；关闭后按原样插件提供的范围和修订号消费命令，输入改变时不删除新正文。候选和命令等待可取消，停用只移除该插件的来源，迟到结果不接回已改变的输入。真实窗口检查覆盖关闭、Escape、两个任务、启停及重启；五个原生任务的对话条数不变，这段只读验收期间，隔离端点请求始终为 20 次，见 ui-context-command-counts.json。已选择的命令不会在弹窗背后重新打开候选菜单。此段只读命令验收的请求数为当时阶段记录。输入控制器、文字补全与带参数命令的后续实现和验收见下一段，不能从 handled 命令推断所有输入结果都已支持。

真实窗口额外发现 sessions.refreshSubagents 缺失会让上下文标签报错，已修复。子任务目录来自官方 subagentCatalog，沿真实父子关系读取各自投影，遇到重复归属、循环或父任务不符时拒绝。冷记录通过官方查询读取并释放观察对象，没有恢复子任务模型资格；子任务只进入列表的 byId，根任务总览的 ids 不增加。原样插件的关系图显示一个根任务和两个真实子任务，合计 3.7k 当前上下文。点击两条子任务分别打开自己的真实要求及回复，运行说明另行折叠；无保存标题和目录标签时，从实际首条用户要求生成显示名称，不冒充已保存标题。该阶段的窗口验收只覆盖历史阅读。后续已增加可续跑子任务的文字继续、即时补充和停止入口，实际运行检查覆盖原父子归属、请求去重、后续模型收到内容、停止兄弟任务互不影响，以及父任务重新授权后恢复同一个冷子任务；新增入口尚未操作真实窗口。子任务工具仍沿用所属根任务的审批，原 DSH 禁止托管子任务直接向用户提问的规则保留。上下文读取没有变化时保留投影引用，避免原样页面每 1.5 秒重新载入并重置滚动；窗口连续多次刷新，滚动位置和图中三个节点的位置保持相同。

固定提交的官方 InputTriggerController、候选菜单、触发检测和引用语法已原样复用；inputTriggers.sessionOf 返回实际控制器，按保留的根会话范围管理、预热、订阅和销毁。已接入文字补全、带参数命令、空格选择、引号路径、目录展开和返回。命令只允许行首位置，去掉前置空白并保留参数；正文中的候选不能取得命令资格。成功后才清空原文；拒绝、取消、输入改变或停用后保留输入，迟到结果不能清空新正文。取消等待不保证撤销插件已经开始的业务。引用输入框现复用同一固定提交的官方草稿编辑器、真实节点、投影、范围映射和撤销。每个根会话保留自己的草稿；正文编辑保留未改动的引用，复制出的名称仅是普通文字。每次发送逐个调用实际来源读取内容，来源停用、读取失败、取消或输入改变时阻止发送且保留原文。已发送消息保存显示原文和明确引用身份，重新编辑时恢复节点并重新核对来源；成功发送后切断旧撤销记录。命令参数同样带入实际读取内容；该阶段命令附件仍明确拒绝，后续接入见下文。此段记录的是原草稿编辑器阶段；公开输入的后续实现见下文，不能将这些阶段结果等同于完整官方客户端。

本轮隔离模型请求由 23 增至 26：一次实际文件发送，一次因跨会话退出编辑状态而作为普通消息发送，最后一次在原会话明确点击“重新发送”替换最新消息。原生根会话条数由 17、11、2、2、8 变为 17、15、2、2、8；失败、取消、命令和只读预览没有追加请求。旧失败历史完整保留，不把本轮描述成零请求验收。最后窗口清空操作因自动审批检查的账户额度限制未执行；资料仍为隔离临时草稿，没有使用正式用户配置。

程序打开指定来源的候选菜单已经接入实际控制器的 menu、launcher 和 headers 订阅；“添加内容”按真实登记来源列出入口，不写入伪造触发文字。选择范围来自官方编辑器的检测坐标和当前修订号，已有长名称引用后仍按实际范围替换。只显示指定来源，不混入原生历史与文件候选。选择、取消、点击菜单外、切换会话和来源移除均按真实控制器处理；取消后的迟到候选不能恢复菜单。菜单入口保留原来的选择，长列表可滚动。窗口检查覆盖前后正文保留、鼠标及上下键选择、实际资料打开、真实参数命令，以及从菜单打开原样 dsh-context；本阶段模型请求保持 26 次，五个会话条数保持 17、15、2、2、8。自拟样例只证明所列输入行为；该阶段完整公开会话输入服务及命令附件仍未接入，后续附件改动见下文。详细记录见 ui-input-launcher-acceptance.json。

前一轮自动审批检查的额度限制已经解除；临时引用验收窗口已关闭，后来菜单验收使用新的临时包。窗口按真实键盘清空输入，不将自动化直接向空编辑器插入文字的未生效探测算作通过；原生输入法的完整行为尚未验收。

插件命令附件已经接入原生选择器、剪贴板保存与真实会话输入。应用只对实际选择或保存的附件发行窗口/会话所属凭据，拒绝任意路径、其他会话、其他窗口或选择后改变的文件。读取时从同一打开句柄核对身份并流式复制为只属于此会话的临时快照，上传后清理快照。图片按官方 PNG/JPEG/WebP/GIF、字节匹配与 20 MB 上限检查，提交真实 base64 字节；普通文件分块交给父进程的官方附件存储，官方 fileUploads 对实际根 agent/session 发行已完成凭据，再由真实 commands 解析为保存的附件引用。编码文件上传也复用同一分块路径，避免受限进程同步外层目录而失败。每块最多 64 KiB，前一块实际写入后才接收下一块；保存失败、取消和会话结束释放等待者。未放宽插件读写权限，也未绕过官方附件规则。
