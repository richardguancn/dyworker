# Cordis 与 DSH 首批兼容改造交付

实施日期：2026-10-05。本次落实原方案的“限定清单”路线，保留 DYWorker 原有任务入口。办公工具和官方待办使用未经修改的发布包。它不是“任意 DSH 插件均已兼容”，原方案中完整 DSH 独立应用、上下文插件全部功能和跨平台发行验收仍未完成。

## 已交付的行为

- 外部 DSH 工具在独立进程中运行，复用固定版本的官方工具、文件、会话和投影组件。DYWorker 的同名服务和已解密设置不传给它。
- 停止、超时和停用会结束所属插件调用；不响应停止的代码也可终止。停止一个会话不会杀掉另一个会话的调用。
- 参数和官方输出会校验；正式任务入口仍经过 DYWorker 的审批。拒绝写入时没有调用插件。文件完成记录来自宿主实际读回和校验，不能只靠插件自称成功。
- 官方待办事件按 DYWorker 会话保存，调用时重放；同一会话的插件调用顺序执行，避免相互覆盖记录。不同会话各自保存。
- 插件接口按宿主及拥有者登记，重复抢占被拒绝。停用会收回自己的接口并等待在途请求结束。请求参数、请求头和停止信号保留。
- 已启用与已启动分别判定。缺少必需服务显示等待原因；检查阶段导入代码移至受限的独立进程，不在应用主进程执行。
- 安装在暂存目录完成下载和验证，成功才切换；失败保留旧版本、依赖和锁文件。正在执行插件工具时不切换版本。所有来源默认禁用安装脚本；只有源码的仓库需要先提供构建产物。
- 浏览器模块复用固定提交的官方模块系统，支持延迟执行和异步分块。只从 DYWorker 的插件环境取依赖，不回退用户的 `~/.dsh`。
- 客户端提供实际会话与工作区集合；未知调用明确失败。停用收回所属界面贡献、翻译和样式，右侧标签同步消失；两个插件同名登记不会互相覆盖。
- 市场支持记录包含版本、宿主版本、日期与实际范围，去掉无范围的“本机已验证”。

## 验证与证据

真实办公文件通过插件自身读取核对内容，并检查文件实际存在及 ZIP 文件头。待办使用两个会话并核对最终事件。取消样例持续写文件且阻塞事件循环，取消返回后再次读取文件大小，确认没有继续写入；另一个会话仍完成办公文件创建。超时使用相同方式检查。

模型入口使用可控的模拟回复触发真实插件执行，不调用收费模型，也不读取正式模型凭据。允许写入时核对文件和完成记录；拒绝写入时确认调用次数为零及文件不存在。升级失败检查使用可控下载结果制造新版启动异常，确认旧插件源码、版本、可用状态和后续写入均保留。

桌面窗口使用独立临时用户目录，实际操作办公插件安装/重新安装/启停，以及内置上下文插件停用/恢复。停用后会话标签及右侧标签消失，轨迹插件保留；恢复后无重复标签。安装新插件不再丢失原有插件说明。窗口宽度 1184、高度 736，无横向溢出。截图见 ui-disabled.png、ui-enabled.png。

macOS 临时应用已实际打包。使用该应用自带的运行程序和包内组件，加载临时目录中未经修改的办公插件，生成并读回 Word 文件。没有在该检查的运行代码中导入开发目录或用户 DSH 库。打包时发现内置 Node 对 fchmod/fsync 的限制，现由宿主校验实际工作目录后完成这些文件操作，保留官方文件发布流程；不会为了通过检查放开全部写入权限。另修正了从 app.asar 入口启动时依赖目录的转换，并新增实际读文件的回归检查；最后实际打开打包窗口，办公插件和两个内置插件均已启动，办公插件停用和恢复通过。窗口截图为 ui-packaged.png。

完整测试 1140 项通过、0 失败、23 跳过（共 1163 项）；真实运行验收 11 项全部通过。插件构建、主程序构建、界面构建和 macOS 临时应用打包均通过。结果在 support-record.json；详细记录分别为 implementation-tests.tap、runtime-acceptance.tap、packaged-check.json。原 assessment.md 和原诊断 results.json 保留，描述的是改造前状态。

## 尚未承诺的能力

1. 完整 DSH 的任务驱动、子任务、压缩、工作流、交互审批及全部客户端页面没有实现。这些插件需要第二层完整 DSH 环境，不能通过补空服务启用。
2. 官方提示组件装配在内部环境中，但尚未把完整提示生成接入现有任务驱动；明确依赖 systemPrompt 的插件判为暂不支持。需要结束 DSH 任务轮次的工具也明确报出不支持，不能默默丢弃其要求。
3. 每次工具调用使用新进程，只按会话重放事件，不承诺插件闭包内长期状态、后台定时任务或多个外部插件在同一 DSH Context 内互调。这些需求属于完整运行路线。
4. 当前客户端仍是有限的界面位置与适配，真实 dsh-context 全部功能未通过窗口验收。内置 DYWorker 上下文/轨迹的窗口验证不能代替第三方完整验收。
5. 独立进程与 Node 权限限制支持故障隔离、停止和误操作限制，不是恶意代码安全沙箱，也没有网络隔离。内置及既有原生 DYWorker 插件仍走原生运行方式。Node 官方明确指出其权限模型不保证防护恶意代码：[对应版本说明](https://nodejs.org/download/release/v24.18.0/docs/api/permissions.html)。
6. Windows、Linux/麒麟/UOS 的真实应用包和文件权限行为未验证；不得据 macOS 结果承诺这些系统已经兼容。没有正式签名、发布、推送或替换用户正在使用的应用。首次下载新插件当前仍需要机器上可用的 npm；本次打包检查使用预先放入临时插件目录的发布包，不等于整台干净机器的安装验收。

## 主要修改位置

独立运行环境在 electron/host/dsh-runtime/，安装切换在 electron/host/plugin-transaction.mts。其余修改集中在插件宿主、兼容检查、路由和工具服务、四类任务共用入口，以及 src/pluginRuntime/ 与插件管理页面。固定客户端模块源码及许可来源说明在 src/pluginRuntime/vendor/dsh-client-modules/README.md。

后续若扩大支持清单，需要对具体固定版本的真实插件重复相同验收，尤其补全提示、长期状态、第三方完整界面及 Windows/Linux 打包验证，不能仅用“已安装”或“模块工厂已执行”作为兼容证明。
