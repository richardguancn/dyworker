# DYWorker 界面外观自定义实施方案

日期：2026-09-27。用途：交给其他模型实施。本文是实施方案，未修改应用代码，未完成新功能或目标系统验收。

## 1. 目标与完成标准

在“设置 → 偏好”中增加“外观”，允许用户统一调整背景颜色、背景透明度、液态玻璃视觉效果、背景图片、界面字体和字号。

完成必须同时满足：

1. 调整能立即预览；保存并重新启动后仍有效；取消、关闭设置、按 Esc 或点击遮罩时恢复已保存外观。
2. 左侧导航、聊天区、输入框、右侧工具面板、菜单和设置页协调变化，不出现只有局部变化的情况。
3. 最大字号、复杂背景图、浅色与深色组合下，正文和操作按钮仍清楚、可用。
4. macOS、Windows、Linux 均具备基础自定义能力；不支持的高级效果有明确说明并自动降级。
5. 不破坏窗口拖动、缩放、阴影、标题栏、输入法、编辑器、内嵌浏览器和现有设置保存。
6. 交付修改文件清单、实际验证记录、目标平台截图和未验证项；不能用编译通过代替跨平台实机验收。

## 3. 页面与交互约定

沿用现有左侧设置导航，新增“外观”。右侧按下列顺序排布，避免一次摆满参数。

### 3.1 主题

- 选项：跟随系统、浅色、深色；默认跟随系统。
- 提供“默认”“清透”“阅读”三个快捷预设。预设只修改本节外观草稿，不立即保存，也不触及其他设置。
- 浅色和深色分别保存自定义背景色；切换主题不会把另一主题的颜色覆盖。
- 默认预设尽量保持现有观感，不擅自给老用户打开玻璃或背景图片。

### 3.2 背景

| 控件 | 建议规格 | 行为 |
| --- | --- | --- |
| 背景颜色 | 常用色板、取色器、十六进制输入 | 作用于全局背景，并派生协调的导航/面板底色；非法颜色不提交 |
| 背景透明度 | 0–70%，步长 1%，默认 0% | 0% 完全不透明；数字越大越能看到应用自己的背景图；文字和图标不一起变淡 |
| 背景图片 | 选择、缩略图、更换、移除 | 本地 PNG/JPEG/WebP 静态图片；支持中文、空格路径 |
| 图片显示 | 铺满、完整显示、平铺；默认铺满 | 完整显示的空白处使用背景色 |
| 图片遮罩 | 0–80%，默认 20% | 降低复杂图片对阅读的干扰；浅色使用浅遮罩，深色使用深遮罩 |

“背景透明度”的精确定义是应用面板对应用背景的透明度，不是整扇窗口一起变淡。无图片时透出基础底色。控件下写明“只调整背景，文字保持清晰”。

如需透出桌面，在玻璃的高级设置中单独提供“使用系统背景效果”。不能把两种透明度混在同一个滑块里，也不能承诺所有系统均能透出桌面。

### 3.3 液态玻璃效果

- 主开关默认关闭。
- 强度：轻柔、标准、明显；另有“轻量效果”开关。
- 开启后包含半透明材质、背景模糊、边缘高光和轻微层次阴影。首期不做持续晃动、鼠标追踪折射或大面积动画。
- 主要作用于侧栏、顶部工具区、输入框外壳、右侧工具栏；正文阅读区保持更稳的底色。
- Linux 默认使用轻量效果；能力不足时改用半透明颜色、静态高光和阴影，不做背景模糊。
- 高级项“使用系统背景效果”默认关闭，仅在支持的平台提供。不可用时显示原因，例如“当前系统使用应用内玻璃效果”。
- 应用内实现为液态玻璃风格，不宣称等同 Apple 原生 Liquid Glass；系统毛玻璃与原生 Liquid Glass 也不是同一功能。

### 3.4 字体与字号

- 显示字体：跟随系统（默认）、无衬线、衬线、选择本机字体。提供中英文、数字、标点的实时样例。
- 界面字号：小、标准、大、特大，对应基准 13、14、16、18px；默认标准。各控件按现有层级映射到基准，而不是全部强制同一字号。
- 正文字号：14–24px，步长 1px，默认 16px。与界面字号分开，便于只放大聊天和阅读内容。
- 显示字体作用于导航、按钮、输入、聊天正文、Markdown 正文；代码、日志保留等宽字体，公式与图标保留专用字体。
- 不强制改写内嵌第三方网页、PDF、图片、导出文件的字体；这些内容只有应用工具栏跟随设置。
- 本机字体只在点击“选择本机字体”后尝试读取；按字体家族去重，支持搜索。不自动下载或安装字体。
- 枚举失败时保留系统/通用字体选择，并允许输入已知字体名称试用；名称缺失或卸载后自动使用后备字体，不能导致空白或崩溃。

### 3.5 预览、保存与恢复

1. 进入设置创建一份外观草稿；调整时实时应用于当前窗口，并显示“预览中，保存后保留”。
2. 在设置内部切换栏目保留草稿；关闭整个设置时，未保存外观回到最新已保存值。
3. 外观页使用独立的“保存外观”“取消”“恢复默认”操作，不把其他页未保存的模型草稿一起提交。
4. “恢复默认”只改外观草稿；点击保存后才持久化。
5. 保存成功后更新已保存基准；保存失败显示原因、保留草稿以便重试，不显示成功。
6. 连续拖动滑块只更新预览，按帧合并；不逐帧写磁盘。
7. 需要原生窗口变化的预览必须经过统一管理；取消、窗口重建、渲染崩溃时恢复最后保存状态。
8. 提供应用菜单“恢复默认外观”作为应急入口；在设置被不合适的字号挤压时仍能恢复。

## 4. 技术实施边界

### 4.1 独立外观存储

建议使用 `userData/appearance.json` 与 `userData/appearance-assets/`，不放进模型配置档案，不同步到工作区，不包含账户密钥。

建议数据结构：

```ts
interface AppearanceSettings {
  version: 1;
  theme: "system" | "light" | "dark";
  background: {
    lightColor: string | null; // null 使用该主题默认色
    darkColor: string | null;
    transparency: number; // 0..70，百分比
    imageId: string | null; // 应用管理的资源 ID，非任意路径或 URL
    imageFit: "cover" | "contain" | "tile";
    overlay: number; // 0..80，百分比
  };
  glass: {
    enabled: boolean;
    strength: "subtle" | "standard" | "strong";
    lightweight: boolean;
    systemBackdrop: boolean;
  };
  typography: {
    family: string; // system / sans-serif / serif / 经校验的字体家族
    uiSize: 13 | 14 | 16 | 18;
    contentSize: number; // 14..24
  };
}
```

- 由主进程统一校验并规范化；渲染进程也校验但不能取代主进程校验。
- 缺字段补默认；有限数值检查、范围钳制、枚举白名单、颜色格式校验、字体名称长度限制。
- 文件缺失使用默认；损坏文件保留为备份后恢复默认；未知更高版本不静默覆盖原文件。
- 原子写入，失败保留原文件；保存请求串行化，必要时带 revision 防止旧请求覆盖新值。
- 保存返回规范化后的完整配置、revision 和实际效果状态；界面以返回结果更新。
- “用户选择”与“本机实际效果”分开：降级不得偷偷改掉用户偏好，实际效果状态不持久化为用户设置。

建议接口：`getAppearance()`、`saveAppearance({ settings, revision })`、`getAppearanceCapabilities()`、`importAppearanceImage()`、`readAppearanceImage(imageId)`、`previewAppearance(settings)`、`cancelAppearancePreview()`、`resetAppearance()`。纯页面样式预览留在渲染端；只有窗口背景/系统材质变化才调用原生预览接口。

所有接口沿用现有 `trustedHandle` 的来源校验，确认调用来自主应用顶层页面，不向第三方网页或内嵌浏览器开放文件读取、字体权限、外观写入。

### 4.3 主题和背景的绘制顺序

由下至上固定为：窗口底色/可选系统材质 → 应用背景颜色 → 应用背景图片 → 图片遮罩 → 面板材质 → 文字与交互层。

- 背景装饰层设置 `pointer-events: none`、`aria-hidden`，尺寸覆盖内容，不占布局位置、不进入拖拽命中计算。
- 禁止给 `.app-shell`、`body` 或窗口使用整体 `opacity`/`setOpacity()` 实现本需求，否则文字和按钮也会变淡。
- 根节点输出明确的 `data-theme="light|dark"`；只有 system 模式监听系统变更。
- 现有所有深色媒体查询改为统一受控选择器或严格限定“没有显式主题”的启动后备规则。必须覆盖系统深色但用户选浅色的反向场景。
- 同步 `color-scheme`、窗口启动底色和主题事件；不允许主进程继续无条件用系统颜色覆盖用户颜色。
- 启动先读取小体积外观配置，再呈现主界面；图片异步读取，期间显示正确纯色，不等待图片而阻塞启动，也不先闪一下默认白色。
- 玻璃关闭或轻量模式下，清除相关 `backdrop-filter`，不只把强度变量设零。尽量复用几个主要面板层，不给每条消息叠加模糊层。
- 系统背景效果只有在整条应用背景链允许透出时才可见；不能只调用系统接口却保留所有不透明底层。普通自定义色使用半透明着色层；关闭系统效果恢复实色窗口底色。
- 背景图片本身不透明时会遮住系统背景，界面应说明；不为“看起来有效”额外降低文字透明度。
- 重要操作、审批、错误提示和设置弹窗保留可靠实底或最低遮罩。图片情况下不能仅根据背景色推算文字对比度，要用实际合成后的截图检查。

### 4.4 图片导入与生命周期

1. 主进程打开文件选择器，读取并校验实际图片格式；不只检查扩展名。
2. 建议输入不超过 20MB、像素总量不超过 4000 万；先检查尺寸再完整解码。超过限制给出可理解的提示。
3. 只接收静态 PNG/JPEG/WebP；动图、多帧图片和 SVG 本期不接收。统一处理方向并缩放至最长边不超过 3840px，去除无需保留的元数据。
4. 生成随机资源 ID，将处理后的图片写入应用专用目录；禁止使用用户传入的任意路径作为读取或删除目标。
5. 主进程按 ID 返回已校验图片字节及 MIME；渲染端创建 Blob URL 显示，替换/退出时释放。配置只存资源 ID，不存 Base64 或 Blob URL。
6. 导入文件作为暂存资源被草稿引用；保存配置成功后才成为正式引用。取消只回收不再引用的暂存资源；旧图片在新配置成功保存后再回收。
7. 清理前重新确认已保存配置及活动草稿的引用；启动时清理过期暂存文件，不能误删当前图片或用户原图。
8. 图片不存在、损坏、读权限不足时恢复颜色背景并提示一次；设置页仍可更换/移除，应用仍能启动。
9. `data:`/`blob:` 已在当前图片策略中允许，优先沿用；开发和安装包均验证，不能只测试开发路径。

### 4.5 字体与字号实现

- 用 `--font-ui`、`--font-content`、`--font-mono`、字号层级变量统一驱动，不用整页缩放实现字体设置。
- 保留中文与拉丁字符后备链。选到只含拉丁字符的字体时，中文仍使用平台可用字体。
- 本机字体枚举优先尝试 `queryLocalFonts()`，必须先做当前 Electron 的能力试验。该 API 有兼容性及授权限制，不能假定存在即能调用。[MDN 说明](https://developer.mozilla.org/en-US/docs/Web/API/Local_Font_Access_API)
- 当前主窗口权限处理只允许 media；不能为了字体枚举放行所有权限或笼统允许 unknown。若当前 Electron 无法安全识别字体权限，使用通用字体加字体名称输入的确定性后备方案，记录枚举不可用。
- 所有字体设置使用 CSS 属性赋值和合法字符串序列化，不能把字体名称拼接成任意 CSS 文本。
- 不把 `document.fonts.check()` 的 true 当作某个本机字体必定已安装的证明。优先依据枚举结果；不能确认时使用样例和后备链，不标记“已确认安装”。
- 字号增大时同步行高与必要的控件最小高度；菜单、输入框、设置内容允许滚动，页脚始终可到达。
- 字体加载完成、字号变化后让编辑器重新测量；图表、布局按需要 resize，不丢输入焦点、文本选择和滚动位置。
- 尊重减少动态效果和高对比度设置；减少透明效果有系统可靠检测时联动，同时保留用户可操作的轻量开关。

## 5. 跨平台策略

| 平台 | 必须交付 | 系统背景增强 | 关键验证 |
| --- | --- | --- | --- |
| macOS | 主题、颜色、图片、透明面板、玻璃风格、字体字号 | 可使用 Electron vibrancy；需运行验证与撤销恢复 | 红绿灯避让、拖动、全屏、失焦后效果、深浅切换 |
| Windows 11 22H2 及以上 | 同上 | 可用 `setBackgroundMaterial`，实际系统设置可能使效果减弱或关闭 | 最大化/还原、贴靠、窗口阴影、不同缩放比例 |
| 其他项目支持的 Windows | 同上 | 不调用不支持的系统背景效果，使用应用内效果 | 不报错、不黑底、不出现多余透明边缘 |
| Linux，包括麒麟/UOS目标环境 | 同上，默认轻量玻璃 | 本期不实现桌面透视、不切换成透明无边框窗口 | 系统边框、边缘点击、中文输入、ARM64、窗口拖动缩放 |
| 普通浏览器预览 | 页面外观与交互 | 无原生窗口效果 | 缺少桌面桥接时明确“仅预览”，不能显示桌面保存成功 |

Electron 官方规定 Windows 背景材质接口仅支持 Windows 11 22H2 及以上；macOS 的 vibrancy 是独立平台能力。[Electron 官方文档](https://www.electronjs.org/docs/latest/api/browser-window#winsetbackgroundmaterialmaterial-windows)

透明窗口有独立的系统行为与限制，因此本方案不通过跨平台开启 `transparent: true` 实现外观自定义。[窗口样式说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)

平台适配细则：

- 能力状态至少区分：用户请求、平台可尝试、实际调用结果、当前降级原因。仅“API 调用未报错”不能作为视觉生效证据。
- Linux 继续保持 `frame: true`、阴影和实色原生窗口底层；不加入透明边距、鼠标穿透或通过轮询恢复点击的逻辑。
- Linux 已关闭硬件加速，不能为玻璃擅自重新开启。先验证轻量模式；用户手动开启更强效果时应可随时恢复。
- 检查当前 Linux 启动逻辑对 Wayland/X11 的选择，记录最终实际使用的后端。Wayland 桌面上通过 XWayland 运行不能写成原生 Wayland 已验证。
- 不新增依赖编译的原生 Liquid Glass 插件作为首期前置条件，避免给 Windows/Linux/ARM64 带来安装风险。
- 原生效果失败立即恢复普通窗口底色与应用内效果，保留草稿与已保存值；不得关闭或重建用户正在运行任务的窗口来强制生效。

## 6. 分阶段执行顺序

以下阶段都属于本次目标，按顺序推进；不要只完成设置表单就交付。

阶段完成条件：移动原图后背景仍在，图片损坏可恢复，文字不随透明度变淡，窗口操作无退化。

### 阶段 C：字体和全界面适配

## 7. 验证清单

### 7.1 自动检查

新增围绕真实行为的测试，建议 `tests/appearance.test.mjs` 与 `tests/appearance-assets.test.mjs`：

- 空配置、旧配置、非法颜色、NaN/Infinity、超范围值、未知版本、损坏文件恢复。
- 保存失败后旧设置仍可读取；连续保存不倒序覆盖；旧外观版本请求被识别。
- 预览后取消恢复；保存后再修改再取消恢复新基准；切栏目、Esc、遮罩、关闭按钮结果一致。
- 系统明暗与显式主题组合；主题变更不改变其他设置。
- 图片导入/更换/取消/保存/重启/丢失；非图片伪装、超大尺寸、资源 ID 越界读取与误删防护。
- Linux 永不设置透明窗口或鼠标穿透；不支持的 Windows 不调用系统背景接口；调用失败能回退。
- 未信任的网页调用被拒绝；浏览器预览缺少桥接时不谎报保存成功。

执行现有检查：

```sh
npm run verify
node --test tests/linux-window-input.test.mjs tests/desktop-contract.test.mjs
node --check electron/main.mjs
git diff --check
```

对新增 `.mjs` 模块也执行语法检查。若已有测试因合法的主题默认值调整而不再适用，只调整预期，不删除 Linux 窗口安全约束。基线失败和新引入失败分开记录。

### 7.2 实际交互检查

| 场景 | 必须看到的结果 |
| --- | --- |
| 首次启动、已有用户升级、完全退出再启动 | 默认合理；保存的外观恢复；没有明显错误底色闪烁 |
| 任意改动 → 取消/关闭/Esc/点遮罩 | 页面和原生背景均回到已保存值 |
| 保存失败 → 重试 | 有真实失败提示；草稿保留；成功后重启可恢复 |
| 纯色/复杂照片 × 浅色/深色 × 最大透明度 | 正文、选中状态、禁用提示、错误提示和焦点可辨 |
| 选择/替换/移除图片，移动源文件，再重启 | 应用管理的背景仍正常；移除后无残影 |
| 字体缺失、权限拒绝、中英文混排、emoji | 可继续使用，显示合理后备字体 |
| UI 18px + 正文 24px，980×660 最小窗口 | 保存/取消可达；无按钮裁切；有需要的滚动区域 |
| 右侧窄面板 + Markdown 表格/代码/长链接 | 表格正确滚动；代码对齐；不挤坏窗口 |
| 连续中文输入、选择文本、撤销、切换字号 | 文本/光标/撤销历史保留，无输入法位置异常 |
| 图表已渲染后切主题/字体 | 图表文字和背景协调；布局重新适配 |
| 浏览器打开网页、切换标签、控制提示层出现 | 网页内容不被强行改写；应用工具栏和交互层正常 |
| 最大化/还原/全屏/拖动/缩放/切屏/失焦 | 边缘点击正常；无额外透明圈；窗口仍接收输入 |
| 调整模型或渠道设置后再检查外观 | 两类保存互不覆盖 |

性能检查使用同一台设备、同一长会话和同一背景图，对比关闭玻璃、轻量玻璃和标准玻璃的连续滚动/输入。记录 CPU 占用与帧耗时；建议标准模式相对关闭状态的滚动帧耗时 P95 增幅不超过 20%，若超出则降低模糊面积/强度，必要时将该平台默认改为轻量。不以一台高性能 Mac 的结果替代 Linux ARM64 验证。

### 7.3 平台实测记录

至少覆盖 macOS、Windows 11 受支持版本、一个不支持系统材质但项目支持的 Windows 环境，以及实际目标 Linux ARM64 桌面。麒麟/UOS 按实际发布目标分别验证；系统缩放覆盖 100%、150%、200%。
