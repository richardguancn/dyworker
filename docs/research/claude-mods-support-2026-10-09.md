# DSH 插件继续对齐与 Claude Mods 支持方案

本文保留 2026-10-09 的研究与方案历史。2026-10-10 已开始实现并验收，当前范围及结果见 [交付记录](./claude-mods-delivery-2026-10-10.md)，不以本文的拟实现清单作为已实现功能声明。

## 当前结论与交付标准

DSH 仍是现有插件层的基准。Claude Mods 可以作为第二种插件格式接入同一个管理页面，但应有独立的格式解析与执行适配。不要把 Mods 模块当作 Cordis 插件调用，也不要为了兼容 Mods 改写全部 DSH 服务。

本轮完成标准：核查官方资料和当前代码，明确两者能够复用的部分、不能直接复用的部分、首期支持范围与验收条件；修复实际复现的 DSH 插件判定问题；运行相关检查和构建。本文是已完成的支持方案，**不是已经实现 Claude Mods 支持的声明**。

本轮修复：只提供配置、没有包主入口的插件，其“检查是否可用”此前错误地尝试执行包主入口，可能显示不可用，而安装实际成功。现在检查与安装使用同一份合成配置，并同样区分配置包和可执行入口。回归检查覆盖安装前、安装后、停用恢复、重启和卸载。保留工作区已有待办配置修复。

## 官方资料和版本边界

核查日期：2026-10-09。以下均为 Anthropic 官方资料：

- [Mods 概览](https://code.claude.com/docs/en/plugins/mods/overview)：Mods 是插件里的函数式事件处理代码，能够改变运行行为和界面。
- [文件、事件及方法参考](https://code.claude.com/docs/en/plugins/mods/reference)：包声明位于 `.claude-plugin/plugin.json`；默认 `hooks/hooks.json` 的 `modules` 指向一个模块；模块导出 `register(on, options)`。配置值来自声明的 `userConfig`。
- [事件处理](https://code.claude.com/docs/en/plugins/mods/events)：处理函数围绕 `next(e)` 组成调用链，可以观察、改写或直接回答事件。
- [Mods 方法](https://code.claude.com/docs/en/plugins/mods/api)：方法由 `$` 提供，包含工具、命令、会话、状态、计时和界面等。
- [界面绘制](https://code.claude.com/docs/en/plugins/mods/interface)：绘制和交互使用专门的界面元素及事件，不能直接当作现有 DSH React 组件挂载。
- [公开类型定义](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts)：本轮下载的文件首行标记版本是 `2.1.277`，早于参考页所述 `2.1.290`；不得把这份文件当作当前完整协议。

公开类型还明确模块环境没有 Node 或 DOM，所有扩展名均按 ES 模块处理，界面元素通过 `$.ui.resolve(e)` 获取。这意味着直接在主进程执行普通 `import()` 会增加插件原本没有的能力，也无法还原其绘制方式。官方公开的是契约和示例；本轮没有取得完整 Mods 执行引擎源码，不能按 DSH 的方式直接复用官方加载器。

## 可以复用的项目基础

以下是对当前工作区代码的核查和设计判断，不是上游兼容性保证。

| 项目现有能力 | Claude Mods 接入方式 | 需要补齐的内容 |
| --- | --- | --- |
| `electron/host/plugin-host.mts` 的安装、配置、启停、恢复 | 管理页面复用，按格式分发到独立执行器 | 本地目录格式、独立版本记录和生命周期；不能送入 npm/DSH 安装流程 |
| `electron/host/services/agent.mts` 的 `tools/pre-execute` | 复用现有规则与审批判断作为最终执行入口 | 完整的工具前后事件链；当前事件只能追加限制，不能改写参数或返回结果 |
| `electron/host/services/tools.mts` 的插件工具归属与审计 | 保留宿主生成的实际工具名，Mods 名称通过映射关联 | `$.tool.register`、`$.tool.call` 及名称映射；不得覆盖内置工具 |
| `electron/host/services/dsh-runtime.mts` 与官方会话进程 | 为 DSH 会话增加同一套语义的接缝 | 不能只给默认会话接入；否则 DSH 会话会漏掉处理函数 |
| `src/pluginRuntime/clientHost.ts` 和 `src/PluginSlotView.tsx` 的界面贡献 | 复用面板归属、显示位置、移除和错误展示 | 将 Mods 返回的元素树转换为宿主可绘制的内容，按钮等动作发回所属模块 |
| 现有会话、取消、日志和持久化服务 | 提供当前会话信息、取消信号和插件私有状态 | 明确插件与会话隔离、重载清理、持久化恢复及活动过期处理 |

共享的是管理体验与宿主能力，DSH/Cordis 原有配置、依赖等待和客户端加载规则继续独立保留。Mods 的状态文件与安装目录也应独立，避免其更新改变现有 DSH 插件树。

## 建议的首期实现

首期支持本地目录安装和固定、明示的能力范围。先让活动记录、操作拦截和简单状态面板完整可用；不先接所有市场，也不宣称第三方 Mods 普遍兼容。

1. **读取与检查。** 识别官方目录结构，解析名称、版本、配置和模块入口，处理相对路径及模块扩展名。安装时读取所有导入文件，使用语法树检查实际事件和方法；无法静态判断的访问显示为待确认，不能靠搜索几个字符串宣布可用。缺失文件、越出插件根目录的导入、未知事件或方法明确报错。读取与检查不执行模块。
2. **独立执行环境。** 为每个会话的插件实例建立可取消的执行环境，编译 TypeScript/JSX，仅提供必要全局值和明确实现的 `$` 方法。插件代码通过宿主桥接操作文件、工具或界面，不直接获得 Electron 主进程对象。执行进程用于隔离故障和终止耗时代码；不能把普通 Node 子进程或 `vm` 本身称为权限隔离。
3. **完整事件链。** 首期拟支持 `session.start`、`session.end`、`turn.start`、`turn.complete`、`tool.call`、`command.run`，以及首期面板所需的界面事件。实现匹配条件、冻结输入、按顺序执行、改写事件和结果、短路返回、取消和错误显示。未实现的事件在加载时拒绝，不能登记成功后静默不触发。
4. **工具接入。** `Bash`、`Read`、`Write` 等官方工具名称及字段需要明确转换，不能只改名称。内部保留实际宿主工具身份、调用标识与会话归属。插件改写后的参数重新校验，再按最终工具和参数运行现有规则与审批；后续结果改写只能改变返回内容，不能冒充宿主确认的文件变更记录。首期不实现可以放宽审批的 `tool.check`；因此依赖该能力的 Mod 会明确不支持。
5. **界面接入。** 首期提供新增面板和状态文字，拟实现 `ui.render`、`ui.press`、`ui.input`、`ui.select` 与 `$.ui.resolve/open/close/invalidate/status/log`，只暴露实际绘制的元素。先支持 Box、Text、Button、Input、Select、Markdown。元素树需要可传输，交互只包含动作标识，所属模块仍在执行环境中处理。终端像素绘制、第三方 Client 模块和替换完整对话行先不支持；不能伪造“桌面支持”来让插件进入不存在的界面位置。
6. **状态与清理。** 提供插件私有、会话隔离的状态及取消计时器。停用、卸载、重载、关闭会话都要移除处理函数、工具、命令、面板和计时器；执行结果带实例版本，旧实例完成后不能写回新实例。持久数据与内存状态分开，恢复时验证数据格式。

这些名称是拟支持清单，不是已实现清单。文件读写、进程、网络和模型请求方法只在对应宿主路径及检查具备后开放。模型请求使用 DYWorker 中用户已配置的服务，不借用 Claude 的登录、订阅或内部会话。`$.session.version()` 等身份信息应如实报告 DYWorker 提供的兼容实现，不能伪装成特定 Claude Code 版本。

执行顺序、错误恢复、超时计算及事件返回结构需要按所选官方契约逐项测试。尤其是处理函数已经调用 `next` 后出错，不能为了恢复再次执行工具；插件显式调用 `next` 重试时，每次仍须走原规则和审批。执行超时后也不能让迟到的改写或副作用继续生效。简单墙钟超时并不等同于官方扣除 `next` 等等待时间的预算规则，应明示差异。首期不伪造托管插件优先级或跳级能力。

## 接入两种会话的执行顺序

默认会话与 DSH 会话应共享同一份能力声明和行为测试，分别连接各自实际执行边界：

```text
用户请求 → 当前会话的 Mods 事件链 → 原会话入口
工具调用 → tool.call → 最终参数校验 → 原规则与审批 → 原工具执行
                                                ↑
                               Mod 不能通过改写跳过此处
工具结果 → tool.call 返回路径 → 模型读取
界面事件 → 可传输元素树 → 页面绘制 → 动作回到所属插件实例
```

不要在 UI 的最终显示阶段才接工具拦截，那时副作用已经发生。DSH 会话应在官方进程的实际执行接缝连接，不能仅靠父进程接收执行后的日志推断拦截成功。

## 首期验收门槛

- 用活动计数、危险操作拦截和带按钮的状态面板三类代表性插件跑完整使用过程。自己的假设样例只证明实现行为；第三方可用清单必须验证其具体版本后加入。
- 验证默认会话和 DSH 会话均触发相同事件；工具改写后审批看到的参数与实际执行参数一致；拒绝时实际工具未执行。
- 验证链顺序、匹配条件、短路、结果改写、明确重试、异常、超时及取消，尤其确认错误恢复不会自动重复执行工具。
- 实际打开页面，操作按钮与输入项；停用和重载后无残留内容，也不继续计数、弹提示或发起后台工作。
- 重启后恢复需要保存的设置与数据，两段会话的计数和状态不互相串用。
- 不支持的事件、方法和绘制位置在安装检查中显示具体原因；不能把“读取成功”“登记成功”显示成“可以使用”。
- 复查现有 DSH 插件的安装、版本判断、配置覆盖、依赖等待、分组、启停、重启及卸载。
