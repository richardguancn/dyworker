# 节省 token 时保留任务要求

更新日期：2026-10-29。

## 当前行为

普通会话整理旧工作记录时，完整保留用户原话、后续纠正和系统约定，只缩短助手的旧工作与工具结果。摘要失败、为空、被截断或任务取消时，不用残缺摘要替换历史；摘要没有缩短材料时也不替换。没有可缩短的工作记录时，不额外调用摘要模型。

新摘要以助手消息保存，避免把模型概括的话变成用户要求，也便于下一次继续整理，防止旧摘要反复堆积。用户自己写了“上下文压缩”等字样的消息，仍按用户原话保留。

本轮实际执行记录独立保存，在整理或裁短之前收集原始结果。不能因模型可见的历史变短，就按旧下标漏掉已执行的操作。连续多次整理后，四份实际文件的原始写入内容和工具结果仍能完整返回，下一轮会话可以继续使用这些记录。

DSH 会话沿用官方的整理、容量检查与持久化流程，在摘要中额外保留被覆盖范围内的真实用户消息。连续整理时，从持久记录和旧整理范围恢复原话，按原顺序去重；不从模型摘要中猜测用户说过什么。模型原始输出与程序补充保留的内容分别记录。长消息末尾、特殊符号、纠正顺序及重启后的后续请求都有检查覆盖。

这两种做法都优先保留要求。如果用户原文自身已经占满可用空间，不能通过丢掉用户要求来强行腾出空间。旧工作摘要仍可能遗漏工作细节，必要时需要回查原始文件或历史；原话保留也不能代替真实模型的任务质量评测。

## 离线对照检查

运行：

```sh
npm run eval:tokens
```

无需配置模型账户，也不会连接付费模型服务。程序在临时目录实际生成并读取文件，运行后清理临时材料。

对照任务包含大量旧工作记录、原始口径，以及放在长用户消息末尾的最终更正。对照方案完整携带历史，候选方案使用当前自动整理。两边分别验证：

1. 任务是否结束。
2. 文件中的编号、金额和状态是否符合最终更正。
3. 实际任务请求是否仍包含完整更正。
4. 文件写入的实际执行记录是否完整保留。
5. 包含摘要和所有任务请求后的总估算消耗是否下降。

检查错误产出的反向用例也纳入测试：即使声明完成、消耗减少，只要文件内容错误，验收仍不通过。

本次离线样例得到：完整历史对照估算消耗 425,107，自动整理方案估算消耗 34,575；两边均生成了符合最终更正的文件。自动整理方案包含一次摘要请求和两次任务请求。数据只说明这个模拟样例的材料传递和估算记账，不是线上节省比例，也不是旧版本与新版本的真实模型完成率对照。

## 后续真实任务验收

使用相同任务、材料和验收条件，比较输入输出总消耗、实际费用、耗时、完成质量与返工次数；费用包含整理、审核、重试和子任务。区分服务实测和本地估算，缓存缺项不能按零处理。不能因为某次回复更短，或工具返回成功，就判定优化成立。

下一批模型分工与读取复用，应在这些实际任务验收通过后逐项加入。本次没有自动切换用户选择的模型、降低普通任务的思考档位或限制正常回复长度。
