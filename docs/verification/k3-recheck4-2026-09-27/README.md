### P1-1：命令文本仍可冒充真实执行证据

位置：electron/agent.mjs:4250、4377–4403。对应用例 1、2。

- 实际只执行 `printf 'upload success'`，没有上传，模型回答“已上传成功”，结果仍为 done。
- result.txt 原内容是“旧内容”，实际只执行 `printf '> result.txt'`，再次读取确认文件未改变，模型回答“已写入 result.txt”，仍为 done。

原因：上传按命令包含 upload 等词判断，文件写入按命令包含重定向字样判断，连引号中的纯文本也被当成操作。应核对真实执行回执和目标变化；命令文本不是完成凭据。

### P1-2：批量上传被错误按工具调用次数计算

位置：electron/agent.mjs:4288–4303。对应用例 3。

模拟一次批量工具成功返回四篇不同草稿编号，声称“四篇全部上传成功”，却被认定只有一次成功而阻止交付。一个调用可以处理多篇，次数不等于文章数。应以具体文章的成功回执计数，同时区分封面、图片等辅助上传。

### P1-3：工作区根目录目标仍会被子目录同名文件替代

位置：electron/agent.mjs:4393–4398。对应用例 4。

用户指定在工作区根目录创建 result.txt，实际只调用 write_file 写入 sub/result.txt，检查根目录只有 sub；回答“已创建 result.txt”仍返回 done。缺省目录时仍退回只比较文件名。应把目标解析为同一工作区下的明确路径后匹配。

### P1-4：混合陈述仍能绕过检查，普通介绍也被误拦

位置：electron/agent.mjs:4208–4222。对应用例 5、6、7。

- “A已上传但B尚未上传”：没有任何上传仍放行，连接词两侧没有独立核对。
- “已生成 a.txt，尚未生成 b.txt”：没有任何文件操作仍放行，文件声明仍被整段否定规则豁免。
- “文件 notes.txt 的用途是记录笔记”：没有声称写入，却被当成创建文件并拦截。

应将用户交付目标与每项操作结果建立对应关系。继续仅补充少数标点、措辞样例，无法形成可靠的完成约束。
