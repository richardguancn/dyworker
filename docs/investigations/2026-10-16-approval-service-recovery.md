# 审核服务故障与开发操作重复确认

## 反馈与结论

截图中的 `docker exec jie2-verify bash -lc ...` 只查询 Qt 系统头文件，但原先不能通过本地只读检查，仍依赖审核服务；专用审核服务返回 403 额度耗尽后，直接转人工。两条 `delete_file` 请求则显示审核等待超时。

另有两个可以独立确认的缺陷：

- 删除审批建议以 `*.cpp`、`*.sh` 记住整类文件；点击“允许执行”还会把同样的规则加入当前任务，扩大了本次删除的实际授权范围。
- macOS 状态把空窗口标题显示为“（无标题）”，选窗时却与原始空字符串比较，误报标题变化。

## 修改

1. 新增严格的容器头文件查询检查。只接受固定容器上的 `bash/sh -c/-lc`，内层仅允许头文件 grep、管道过滤、固定行数 head/tail 与 echo；实际文件参数必须位于 `/usr/include/`。不接受目录回退、动态展开、文件输出、后台任务、环境注入、提权选项或夹带其他命令。该证明只作用于 reviewer 的快速检查，用户钩子、外部路径检查和只读模式仍先执行。
2. 自定义审核服务发生认证、额度、连接或超时故障时，使用本次任务的主模型复核同一份完整材料；仅在主模型与审核服务配置不同时启用。两次审核共享原有 30 秒总时限，首次最多使用一半时间，停止会同时取消等待。明确 ask/deny、资料过长、缺少界面事实和无法解析的结论不触发换模型复核；迟到结论不能覆盖已经结束的审核。
3. 审核请求关闭可关闭的深度思考。额度耗尽和认证错误改用简明说明，不再把整段服务商错误正文塞入审批卡。无法完成复核时仍转人工，不因服务故障直接放行。
4. 删除不再生成或匹配路径通配允许规则，包含旧版本保存的删除通配规则。删除保持逐个对象审核，人工批准只记录本次具体操作。
5. macOS 选窗时将空标题与状态所显示的“（无标题）”按同一个值比较；窗口不存在或真实标题改变时仍停止。

普通文件删除仍须结合用户任务判断；服务都不可用时不会擅自删除。任意容器命令、结束进程和无法识别目标的界面操作也没有获得新的自动放行权限。

## 验证

- 新增专项测试 12 项全部通过：包含专用审核 403、超时、两路不响应、停止、迟到结论、明确拒绝、相同服务去重，以及真实临时文件的允许删除与拒绝保留。
- 实际回放两次同扩展名文件删除，第一项人工允许后，第二项仍单独询问，拒绝后文件仍在。
- 11 个相关测试文件在首次专项 10 项的版本下共检查 384 项：362 项通过、22 项按环境条件跳过、无失败。之后补充的两项专项检查也通过。
- 直接在本机现有 `jie2-verify` 容器执行截图的完整只读查询，返回 `wl_display` 声明。第二个 `QNativeInterface` 查询没有匹配输出，未把这一情况描述为找到了声明。
- 再通过 `runAgent` 实际执行同一容器查询，使用模拟的任务模型发起工具调用；确认真实工具输出含 `wl_display`，没有调用审核服务，也没有请求人工确认。
- macOS 空标题选窗使用真实助手源码执行隔离回放，确认空标题成功、改名和窗口消失仍拒绝；未操纵真实桌面窗口。
- `npm run build:electron`、`npm run build:renderer` 和 `git diff --check` 通过。

审核故障响应与复核结论采用本地模拟；没有测试真实云服务额度恢复，没有连接真实微信或 GPU 服务器，没有更新用户已安装的程序。
