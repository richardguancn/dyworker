# 2026-10-21 空闲 CPU 占用复查

用户截图中的 DYWorker 主进程 CPU 为 30.0%。本次检查的是正在运行的正式应用，主进程 PID 94728、界面进程 PID 94779、图形进程 PID 94742。

## 现场情况

第一次读取运行状态时，主程序仍有一个活动任务，关联会话为“大亚湾业务数据查询”：`activeAgents.size = 1`、`runningTaskCount = 1`，自动唤醒和渠道任务数量均为 0。同期主程序函数采样出现 `requestModel`，界面存在两个运行状态动画。

随后再次读取时，活动任务、自动唤醒、渠道任务均为 0，运行状态动画也已消失。这是观察到的状态变化，本次没有停止任务、重启应用或修改用户设置。不能把前一次存在活动任务的测量称为纯空闲测量，也不能单凭这些信息认定截图的 30% 全部由该任务导致。

## 确认任务全部结束后的测量

在测量前后各核对一次任务状态，中间连续 20 秒每 2 秒记录一次进程 CPU 百分比、驻留内存和累计 CPU 时间，共 11 次。

| 进程 | 瞬时读数范围 | 20 秒累计 CPU 时间增加 | 由累计时间换算的平均占用 |
| --- | ---: | ---: | ---: |
| 主程序 | 0.0%～0.4% | 0.05 秒 | 约 0.25% |
| 界面 | 1.9%～2.6% | 0.44 秒 | 约 2.2% |
| 图形处理 | 0.0% | 0.01 秒 | 约 0.05% |

累计 CPU 时间的显示精度为百分之一秒，换算平均值也受该精度限制。图形进程瞬时读数均为 0.0%，并不表示它在整个窗口完全没有执行。

本次没有复现“所有任务均已结束后主程序持续占用 30% CPU”。这里只记录这 20 秒的结果，不能据此排除其他页面、后续时间段或其他任务收尾条件下的异常。

## 空闲时为何仍有少量工作

现有程序保留计划任务到期检查、界面及插件状态刷新等工作。例如计划调度每 10 秒检查一次，普通会话的模组面板每 1.2 秒读取一次状态。它们可以在用户没有新发任务时继续发生，但定时器存在本身不能证明它们就是截图 30% 的原因。

当前界面约 2.2% 的占用仍有进一步优化空间。本次未对各刷新路径做逐项停用对照，因此不把全部界面消耗归给某一个定时器，也未为消除这次未复现的主程序 30% 问题而修改产品行为。
