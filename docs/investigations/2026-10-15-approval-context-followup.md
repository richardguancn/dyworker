# 配置元信息与外部状态工具的审批补充修复

## 本次反馈

微信日志中，仅统计 `.env` 大小、行数和键名的四条操作仍被敏感路径守卫直接要求人工确认。
截图中，`binary_session {}` 被解释成需要新目标；审核说明还把较早的清理建议当成了用户限制。

## 原因与改动

1. 原守卫按配置文件路径触发强制确认，没有区分输出完整值与受限元信息。
   新增 `sensitive-metadata.mts`，仅证明固定形式的键名提取、计数与 SSH 目录属性查询。
   这类操作交审核助手核对整条命令和用户任务，并非无条件放行。
   完整配置读取、任意脚本读取、按秘密值计数探测、上下文行输出、动态执行、重定向等不能使用该证明。
   若同一命令仍有私钥或其他秘密读取，继续强制确认；用户和工作区强制确认优先。
2. 复用原有 shell 词与复合段解析，抽到 `shell-syntax.mts`，不改变原解析行为。
3. 审核和影响说明现接收当前实际登记的工具描述、完整输入约定以及访问检查依据。
   空参数是否合理根据接口判断，接口材料不是用户授权，第三方描述不能改写审批政策。
   当前接口材料参与决策缓存，接口行为变化后重新审核。
4. DSH 与机器人入口同步提供工具描述。审核政策明确区分状态查询与打开新目标、
   正常任务准备与最终目标、工具建议与用户限制。影响说明不得补造平台支持、残留状态或外发结论。
5. 提醒执行助手优先使用既有连接入口和配置，不为了解凭据格式反复变换命令读取秘密。

## 实测与检查

- 通过项目的 `McpClient` 启动本机已安装 REA，读取实际工具定义，并真实调用 `binary_session {}`。
  返回 `isError=false`，没有活动目标；分析活动为 `not_observed`、提供方列表为空。
  实际定义明确说明该工具查询当前目标、提供方、能力与服务身份，不启动分析；三个输入字段均可省略，示例为 `{}`。
  测试夹具只保留输入定义、描述与声明，不包含庞大的输出结构，也不包含实际机器状态。
- 在临时目录实际执行微信日志前四条命令，使用测试配置与版本诊断替身，不连接远端。
  验证输出包含配置键名与计数，不包含测试密码；审核收到受限输出的检查依据。
- 新增 8 项专项检查，覆盖真实接口材料、空参数状态查询、较早清理建议、接口改变重新审核、
  DSH/机器人一致性，以及秘密读取、任意正则、追加上下文、动态执行、重定向和混合命令不能伪装成元信息检查。
- 13 个相关测试文件共 510 项通过；最后针对新逻辑及安全边界复查 51 项通过。
- `npm run build:electron`、`git diff --check` 通过。

审批模型回复在自动检查中由本地模拟服务提供，用于验证完整材料、判断分支和实际执行结果。
真实 REA 工具调用验证了空参数的接口行为，不等于验证所有云端模型都会作出同样判断。
本次没有连接真实微信、QQ 或 GPU 服务器，也没有更新已安装的 Linux 程序。
