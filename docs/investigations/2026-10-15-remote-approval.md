# 微信远程排查反复审批修复

## 问题与完成标准

用户提供的连续排查记录包含 39 次审批，其中 10 次直接提示审核资料过长。
同时存在保存说明被当成读取 SSH 文件、嵌套命令被拆出假路径、微信详情只发送前 400 字符的问题。

本次验收要求：历史批准的正文不无限挤占审核输入；用户原话和禁止事项完整保留；当前操作完整送审；
公共 SSH 材料按实际用途审核；私钥访问和用户强制确认不被绕过；微信完整展示原因与操作；
连续多步流程真正执行，并验证未授权步骤没有执行。

## 改动

- `approval-context.mts`：小批准记录保留完整参数，长记录改为包含 SHA256 和目标的索引；
  送审凭证总长度限制为 6000 字符，优先保留较新的记录。未展示的正文不能成为放行依据。
  原批准记录仍在任务内保留，用户原话、真实答复和工作区要求不因凭证整理而省略。
- `agent.mts`：在线审核改为估算完整输入总量，预算内完整核对长操作；超过容量仍转人工，
  不截掉禁止要求或命令尾部。本地小模型保留原来的较小容量和人工确认限制。
- 审核前读取工作区内当前入口脚本，最多三份、每份不超过 32000 字节；不执行脚本，
  不读取其引用的配置凭据。访问先经过用户规则与策略插件，软链接不能越出工作区。
  脚本正文及其内容标识参与决策缓存，内容改变后重新审核。
  执行任务准备的远端脚本时，还提供同名本机任务文件、原始写入的内容标识和相关实际上传记录；
  普通分步检查不会挤掉这些文件记录，也不因同名就宣称远端内容已被证明相同。
- DSH 与机器人入口复用同一套批准凭证、入口脚本核查和公共文件审核规则。
- 敏感路径守卫仅检查已知文件工具的实际目标，不扫描写入正文；保存记忆时提到路径不表示读取。
  绝对路径公钥读取检查软链接，单独的公钥指纹查询不当成私钥读取。
  复合命令仅引用公共 SSH 文件时，仍先进入审批，再允许审核助手核对用途；
  同时出现私钥、SSH 目录或其他秘密引用时，继续强制人工确认。
  用户或工作区钩子不能通过声明 `reviewable` 取消强制确认。
- 命令路径提取只识别真正的环境赋值和选项赋值，只对 PATH 类变量拆分冒号；
  不再把嵌套命令中的等号、地址和表达式碎片解释成路径。
  批准一条命令不会把命令参数中的目录变成后续任意本机访问的许可。
- 微信和 QQ 使用完整审批消息，原因通过独立字段传递并优先展示；完整操作由渠道已有分片发送。
  不从命令正文提取原因，不重排命令内容。
- 影响说明读取完整操作；无法获得完整材料时回退为有限的确定事实。
  兜底说明按实际引号边界拆分命令，至少展示真正运行的入口脚本，避免只显示末尾过滤命令。

## 本地验证范围

`tests/remote-approval.test.mjs` 覆盖以下场景：

1. 四十条长批准记录不会挤掉用户原始限制。
2. 在线审核完整接收超过旧长度上限的用户要求与操作，尾部禁止要求仍有效。
3. 保存说明、公钥读取、私钥读取、公钥文件软链接与授权公钥修改。
4. 日志中的远程嵌套命令形式不会拆出假路径，真实本机外部路径仍被识别。
5. 入口脚本变更、访问受限、工作区外软链接不被误用。
6. 微信长审批分片前后原文一致，理由优先展示，命令内相似文字不会被重排。
7. 长命令末尾的写入仍进入影响说明。
8. 在临时目录真正执行四十步模拟排查，交替使用两个已声明目标；准备确认后常规检查继续执行。
   新增目标被人工拒绝，秘密读取和停止后的检查被审核拒绝；逐行核对执行记录证明只有四十步实际执行。
   全程不连接真实远端服务器。
9. 同一命令的脚本改变后重新审核，拒绝后的文件没有生成。
10. 命令参数中的外部目录不会变成随后的本机读取权限。
11. DSH 和机器人处理公共 SSH 引用、私钥与强制确认，并在四十条长批准记录后正常审核。
12. 分步执行远端脚本时仍能核对原始写入与上传记录；检查记录不会挤掉上传事实。

这些测试中的模型回复由本地模拟服务提供，用于验证审批资料、分支、授权隔离和执行结果，
不代表真实云端模型一定给出相同判断。未向真实微信或 QQ 发送消息，未连接 GPU 服务器，
未替换已安装的 Linux 或 macOS 应用。

## 验证结果

- 审批、代理执行、宿主、微信/QQ、DSH 渠道入口等 12 个相关测试文件：502 项通过。
- 初次全量检查：1718 项，1663 通过、31 失败、1 取消、23 跳过；这轮检查发生在修正测试入口依赖之前。
  其中微信/QQ 测试环境缺少新格式函数的依赖，已修正并在上述 502 项中重新通过。
- 受当前隔离环境限制无法启用系统隔离功能的 5 项检查，获得权限后在隔离限制之外重跑，全部通过。
- 受禁止本机端口监听影响的 5 个测试文件，在隔离限制之外重跑：55 项通过。
  这些检查使用临时目录与本机模拟服务，不访问真实业务服务。
- `npm run build:electron`、`git diff --check` 通过。

没有把最初的全量检查记录表述成整套检查一次性全过；相关失败按上述方式分别完成复查。
