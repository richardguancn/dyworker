## 1. 目标与完成标准

在现有右侧浏览器中，让助手完成“观察页面 → 操作 → 等待 → 再次观察 → 核验结果”的连续任务。用户全程看到同一个网页，随时点“我来接管”，手动处理后可让助手继续。外观参考用户截图中的标签页、地址栏、细边框和底部接管浮条，沿用 DYWorker 品牌与主题。

本方案的交付标准：核实项目现状；确定实现路线、接口、控制权规则、麒麟边界；给出分步实施与可重复验收要求。本文不代表功能已完成，也不代表麒麟已实测。

功能实施的完成标准：

1. 右侧显示真实网页，模型确实读取当前页面或截图，操作的就是用户看到的目标标签页。
2. 能完成中文查询、表单填写、滚动、选择、拖动、跨页流程、下载和结果核验。
3. 接管立即撤销后续自动输入；继续前重新观察；停止、关闭页面、切换任务、断网和页面崩溃均可恢复或清楚结束。
4. 不串任务、不误用过期控件、不在结果不明时重复提交；原有浏览器功能不退化。
5. 在真实麒麟 ARM64 环境完成安装、启动、中文输入和任务验收。其他架构、原生 Wayland 单独记录，未验证不得写“已兼容”。

首版范围是右侧内置浏览器。外部 Chrome/360/奇安信浏览器、WPS、系统桌面和原生文件选择窗不是首版自动操作对象；需要它们时转人工接管，不偷偷升级到全桌面控制。

## 2. 参考 Codex 的方式

OpenAI 官方浏览器文档确认：Codex 可在内置浏览器打开页面、点击、输入、查看渲染结果、截图并验证工作；网站授权与敏感动作确认分别处理。本文参考这些可见能力，不声称拥有或复制了 Codex 桌面端内部运行代码。[官方 Browser 文档](https://learn.chatgpt.com/docs/browser?surface=app)

OpenAI 的 Computer Use API 要求应用提供实际执行环境，工具调用并不会自动操作本地浏览器；应用执行动作并回传观察结果，保持会话连续。可采用自定义工具；不必为了浏览器操作更换整个模型循环。[官方 Computer Use 指南](https://developers.openai.com/api/docs/guides/tools-computer-use)

| 参考能力 | DYWorker 的落地方式 |
| --- | --- |
| 用户与助手共享网页 | 复用右侧现有标签页，不另外打开一个不可见浏览器 |
| 查看状态后操作 | 文字/控件观察与真实截图结合，绑定观察编号 |
| 点击、输入和复合交互 | 同一个页面控制器提供语义操作与坐标操作 |
| 操作可见、随时接管 | 宿主界面显示状态、目标提示和接管按钮 |
| 连续执行与自查 | 每步或短动作组结束检查实际页面，失败重新观察 |
| 权限与任务范围 | 复用项目审批和审计，增加任务级浏览器控制范围 |

截图中的发光边框、底部浮条是视觉参考，不把截图里的对话内容当开发指令。文件上传是 DYWorker 后续自主扩展：所核对的官方 Browser 页面明确说明内置浏览器不能自动上传，不应把上传宣传成“照搬 Codex 已有能力”。

## 3. 当前代码事实与必须修正的缺口

以下结论来自本次源码核对，属于静态核查，不是运行验收。

| 位置 | 已有能力 | 本次要补的部分 |
| --- | --- | --- |
| `src/App.tsx`：`ToolPanelTab`、`bindBrowserWebview`、右侧 `aside` | 多标签页、地址栏、历史/下载弹窗、缩放、设备模拟、常驻 webview | 控制状态、接管浮条、任务归属、操作提示 |
| `electron/browser.mjs`：`BrowserAgent` | 打开、正文、前 60 个交互元素、点击、填写、保存截图、下载监听 | 稳定观察、复杂控件、视觉操作、等待、取消、结果核验 |
| `electron/main.mjs`：`activeEmbeddedBrowserContents`、`createExtraToolRouter` | webview 登记、可见页上报、浏览器工具路由 | 明确绑定任务/运行/标签页；移除自动操作路径的任意回退 |
| `electron/preload.cjs`、`src/types.ts` | 浏览器宿主通信 | 控制状态事件及接管/继续/停止接口 |
| `electron/agent.mjs`：外部工具结果处理 | 已能接收 `extra.images` 并向模型提供图片 | 浏览器观察返回图片、元数据与降级状态；无需重建图片通道 |
| `electron/risk.mjs` | 浏览器和桌面操作已有统一风险分类 | 按具体动作及授权范围判定，不能只按工具名字放行 |
| `electron/main.mjs` 启动逻辑 | Linux 关闭硬件加速；部分 Wayland 环境有 XWayland 重启路径 | 保留现状，实机验证，不宣称原生 Wayland 已解决 |

特别注意：

- `BrowserAgent.ensureContents()` 优先使用缓存的 `this.contents`；当前页面选择又可能回退到最后创建的 webview。界面注释中的“只作用于可见页”不能代替实际绑定检查。
- `browser__screenshot` 目前只写文件并返回路径，不返回 `images`。模型没有因此自动看到截图。
- `window.__dyworkerRefs` 是页面可修改的全局数组，编号没有观察版本，也不覆盖 iframe 与复杂控件；不能继续作为可靠控制凭证。
- `Number(args?.ref) || 0` 会把无效输入变成第一个元素编号；必须严格校验，不能猜测目标。
- 点击脚本返回“已点击”不等于业务完成；当前输入实现主要面向普通 input/textarea。
- `createExtraToolRouter` 接收的取消信号没有传给 `BrowserAgent.handle`。定时任务、渠道等没有 renderer 的调用路径也可能取得全局浏览器对象，必须拒绝隐式访问。
- 新窗口目前统一拒绝；下载既有主进程显示监听也有 Agent 保存监听。扩展时统一归属和生命周期，避免重复保存和监听泄漏。

## 4. 技术路线：复用内置网页，独立控制层

选择“现有 webview + 主进程浏览器控制器 + 受限 Chromium 调试协议动作”。语义控件定位优先，画布、自定义控件等使用真实截图和坐标补足。生产环境不安装另一套 Chromium，不新增全局远程调试端口，不用系统鼠标控制网页。

Electron 的 `webContents.debugger` 提供本进程内的调试协议通道，可按目标会话发送命令，断开时有事件。[Electron Debugger 文档](https://www.electronjs.org/docs/latest/api/debugger)

建议分层：

```text
现有 Agent 与审批
        ↓ browser__* 工具
BrowserControlManager（授权、任务绑定、状态、取消、串行队列）
        ↓
BrowserPageAdapter（观察、控件定位、截图、输入、等待）
        ↓
已登记的 webContents / iframe target
        ↕ 状态事件
右侧 BrowserControlOverlay（可见状态、接管、继续、停止）
```

协议层由应用内部封装白名单操作，模型不能直接调用任意 CDP、任意 JavaScript、读取 Cookie 或浏览器存储。第一版不开放代码执行式浏览器 REPL；未来确有收益时再做独立隔离与权限设计。

保留现有 webview 的理由是减少本次迁移范围，而非认定它是长期最优容器。Electron 官方建议考虑 `WebContentsView` 等替代方案；因此本次必须抽出页面适配层。若麒麟验证发现无法修复的叠层或输入问题，再另开容器迁移阶段，同时验证浮层遮挡、布局、焦点与弹窗，不能仅更换组件名。[Electron webview 文档](https://www.electronjs.org/docs/latest/api/webview-tag)

`capturePage()` 可截取页面；`sendInputEvent()` 存在宿主窗口需要聚焦的条件，所以不能把它当作所有环境下的无条件后备输入路径。首选适配层协议输入；只有通过焦点核验且已实测时才用后备路径，否则暂停。[Electron webContents 文档](https://www.electronjs.org/docs/latest/api/web-contents)

## 5. 右侧面板交互

沿用现有标签栏与地址栏，不新建独立“Computer Use 页面”。视觉结构如下：

```text
┌ 网页标签 · 助手图标              ＋  展开 ┐
│ ← → 刷新  [ 当前网址                  ] … │
│ ┌────────────────────────────────────┐ │
│ │                                    │ │
│ │           当前真实网页              │ │
│ │       轻量目标框 / 动作提示         │ │
│ │                                    │ │
│ └────────────────────────────────────┘ │
│  助手正在操作 · 02:18   [我来接管] [停止] │
└────────────────────────────────────────┘
```

- 启动：用户提出浏览器任务后，定位/新建目标标签页并展开右侧；明确任务及站点范围后开始。已有明确授权时复用，不要求每次点击都确认。
- 运行：受控页细边框使用现有主题色；浮条显示“助手正在操作”、当前步骤短句、有效运行时长和“我来接管”。等待模型时显示“正在思考下一步”，不能伪装成正在点击。
- 接管：点按钮后立即显示“已由你接管”，网页恢复手动交互；浮条变为“继续交给助手”“结束操作”。验证码、登录、原生弹窗使用同一路径。
- 暂停：显示清楚原因，如“页面已切换，操作已暂停”“页面连接已断开”；提供继续或结束，不只显示通用报错。
- 完成：提示“已完成”及可查看的结果，边框消退，网页保留。只有结果已核验才显示完成。
- 停止不关闭网页，不自动清空表单。关闭标签页或任务结束则释放控制资源。
- 控制条由宿主绘制，禁止注入远程网页。页面截图只包含网页，不包含浮条和标注；标注使用已校验的页面坐标映射。
- 首版在网页底部预留约 64px 宿主控制区，浮条呈胶囊样式，避免挡住网页底部提交按钮。布局切换导致视口改变时使旧观察失效；控制状态切换保持预留区高度不变。
- 自动操作时宿主输入屏障拦截落入网页的真实点击/键盘，不影响左侧对话。点击屏障触发接管并吞掉该次点击；用户接管后再次点击网页，避免同一次点击误提交。鼠标移动不触发接管。
- 工具栏导航、标签切换、面板隐藏/折叠、切换任务都会先暂停再执行手动动作；不在后台悄悄操作隐藏页面。缩放、调整宽度、设备模拟使观察失效并暂停当前待执行动作。
- 窄面板约 360px 宽时短句省略，保留接管与停止。历史、下载、清理数据仍在二级菜单；清理仍二次确认；地址建议宽度仍不超过地址栏。
- 测试深浅主题、键盘 Tab 焦点、屏幕阅读状态提示、减少动态效果。发光只做轻提示，不做持续闪烁。

## 6. 控制权与并发规则

主进程是唯一状态来源；React 只展示状态和发送控制请求，不自己决定“已暂停”。首版同一个应用窗口同一时刻只允许一个浏览器自动操作运行。

状态：`idle → acquiring → running`；运行中可进入 `awaiting_approval / human_control / paused`；最终进入 `completed / stopped / failed`。恢复统一经过 `acquiring` 和新观察。

每个控制会话保存：`controlSessionId、ownerSessionId、runId、tabId、webContentsId、leaseEpoch、status、allowedOrigins、grants、AbortController、actionQueue`。来自 renderer 的登记必须校验真实宿主归属；不能凭任意数字取得网页权限。

必须满足：

1. 每次观察和每次动作都检查任务、run、控制代次、目标页、可见性及授权。没有目标就返回 `TARGET_UNAVAILABLE`，禁止回退“最后创建的页面”。
2. 页面动作串行；模型一次给出多个工具调用也不能并行输入。同一共享浏览器分区不允许两个任务交错写操作。
3. 接管/停止请求优先于动作队列：同步递增 `leaseEpoch`、撤销执行许可、取消等待和后续输入，随后发送确认事件。旧模型回复、旧审批回调和迟到的下载回调不能恢复旧许可。
4. 在每个按下/释放、字符组、拖动分段之前重检取消。中断后只允许必要的按键/鼠标释放，防止一直处于按下状态。
5. 已经发出的网页请求无法保证撤回；界面不能承诺撤销已发生的提交。结果不明时标记 `OUTCOME_UNKNOWN`，恢复后先核查业务状态。
6. 接管后停止向模型持续发送该页观察；取消关联浏览器思考/执行分支，保留任务上下文。旧运行按暂停原因结束，继续时用新 run/epoch 从当前页面继续，不能把接管记成整个任务完成。
7. 关闭页面、销毁 renderer、取消任务、模型异常、超时、调试通道断开均释放控制和监听。重启只恢复网页/记录，不恢复“正在自动操作”。
8. 渠道、定时和后台任务没有可见宿主绑定时，不提供可执行的浏览器控制；返回“请在桌面打开此任务”。不得复用全局页面。

## 7. 观察、动作与返回契约

保留现有 `browser__*` 名字作为兼容入口，但全部经过同一管理器和授权检查。旧 `click/type` 没有有效观察时要求重新观察，不能绕过新控制层。

建议对模型按需暴露以下工具，具体 JSON Schema 随实现提交：

| 工具 | 核心输入 | 结果 |
| --- | --- | --- |
| `browser__open` | `url`、可选 `tabId` | 已绑定的目标、导航结果、初次观察 |
| `browser__observe` | `tabId`、`mode: auto/text/visual`、可选内容范围 | 观察编号、URL/标题、控件、截图、视口和能力 |
| `browser__act` | `tabId`、`observationId`、`actionId`、单个 `action` | 动作状态、后续观察、是否达到预期 |
| `browser__wait` | `tabId`、条件类型和值、有限超时 | 条件满足或具体超时原因、新观察 |
| `browser__tabs` | `list/open/activate/close` 与明确目标 | 本任务可访问的标签页列表或操作结果 |
| `browser__screenshot` | `tabId`、可选工作区路径 | 模型可见图片；仅显式需要时另保存证据 |
| `browser__downloads` | 查询条件 | 本任务下载状态、完成文件与失败原因 |
| `browser__handoff` | `reason` | 请求用户接管并暂停浏览器分支 |

`action` 用严格联合类型：`click / double_click / hover / type / keypress / scroll / drag / select`。`type` 明确 `replace/append`；`select` 指明 option 的 label 或 value。`target` 只能是当前观察的控件引用，或该截图内的坐标。滚动应支持嵌套容器。上传另设工具，不能混入任意输入动作。

模型不可调用“恢复控制权”；接管后的继续必须来自用户界面/明确用户指令。每步完成自动重新观察，首版不接受任意长动作批次，减少接管等待与误操作。

返回值兼容现有 `{ ok, result, images }`，新增机器可读 `data`：

```text
data = {
  controlSessionId, tabId, observationId, actionId,
  documentEpoch, viewportEpoch, capturedAt,
  url, title, status, errorCode,
  viewport: { cssWidth, cssHeight, imageWidth, imageHeight,
              devicePixelRatio, zoomFactor, cropX, cropY },
  elements: [{ ref, frameId, role, name, rect, enabled, checked }],
  capabilities, verification
}
images = [{ mimeType, data }]
```

`result` 包含供模型理解的精简状态；`data` 由内部管线保留，不假设当前 Agent 会自动读取新增字段。图片通过现有 `extra.images` 管线送入模型，调整现有“本机应用截图”说明为带目标标签和观察编号的浏览器描述。缺少图片能力时必须返回能力限制。

### 7.1 可靠观察与复杂页面

- 使用 Accessibility/DOM 信息形成紧凑语义树；节点身份、frame、观察代次保存在主进程或受隔离执行上下文中，禁止依赖页面可写全局变量作为授权或绑定依据。
- 控件超过数量/字数限额时支持按容器、可见范围或关键词继续读取；明确返回截断信息，不再永远只有前 60 个。
- 操作前检查节点仍属于同一 document/frame、可见且可操作、边界有效，并做命中/遮挡检查；失败返回 `STALE_OBSERVATION` 或 `TARGET_NOT_ACTIONABLE`，重新观察后再决定。
- 不因任意无关动画就清空全部引用：导航、frame 重建、viewport 变化硬失效；一般 DOM 变化在动作前重验节点和命中结果。
- iframe 明确 frameId；跨域/OOPIF 需要目标子会话管理，不能假设主页面脚本能穿透。首版支持普通同源/跨域表单；无法定位的 frame 明确降级为已校准的整页视觉操作或人工接管。
- 支持开放 Shadow DOM、普通 select、复选框、contenteditable；关闭 Shadow DOM/画布走视觉路径，不能虚报 DOM 已覆盖。
- 快照不回传 password 值、隐藏字段、Cookie、令牌或整页存储；截图遇到敏感输入按敏感区域策略遮罩或交给人工，登录接管期间停止采集。

### 7.2 截图坐标

- 模型坐标相对于当前返回图片。图片像素映射到页面 CSS 像素，再由适配器传给输入协议；不得再加宿主窗口/地址栏偏移，也不得重复乘 DPR。
- 未裁剪图片：`cssX = imageX × cssWidth / imageWidth`，Y 同理；裁剪图再加 CSS 裁剪原点。设备模拟及 visual viewport 的额外变换统一由适配器提供并测试。
- 页面缩放、面板宽度、DPR、设备模拟、截图尺寸变化都会更新 `viewportEpoch`；旧坐标操作必须拒绝。
- 默认按需截图，不录制/传输全屏视频。先记录原始尺寸，必要时缩放并附映射；局部高分辨率截图用于小字或密集控件。

### 7.3 等待、重试与完成判定

- 等待 URL、元素、文本、加载结束、下载结束或局部稳定，均有超时和取消；不把长期连接页面的 network-idle 作为唯一条件。
- 建议默认：单动作 10 秒、导航 30 秒、条件等待 15 秒；浏览器分支 60 个动作或 10 分钟后暂停。这些是可配置初始限额，不是实测性能结论。
- 只对可确认未产生副作用的定位/读取重试，最多两次。发生提交、上传、删除、付款或结果不明时先查最终状态，禁止自动再点一次。
- `actionId` 在控制会话内去重，缓存已执行结果；它防止本应用重放，不能保证远端业务恰好执行一次。崩溃恢复视为结果未知。
- 工具成功分为“输入已派发”“页面状态已更新”“业务目标已确认”。最终完成要给出页面证据或文件结果，不能只用“点击成功”。

## 8. 模型适配和授权

复用现有模型设置与任务循环，不强制用户切换 OpenAI，也不写死某个模型名。

| 模型实际能力 | 可用操作 |
| --- | --- |
| 支持工具和图片 | 语义定位 + 截图 + 坐标操作 |
| 仅支持工具/文字 | 普通可识别控件；视觉区域明确请求接管 |
| 配置了独立视觉服务 | 作为可选辅助，需要验证坐标/图片契约与数据流向，不默认调用云端 |
| 无可靠工具调用 | 仅手动浏览，解释限制 |

当前 Agent 在图片被模型拒绝后可能禁用图片输入。浏览器能力必须同步降级并停用坐标动作，不允许丢掉图片后继续盲点。实现时分别测试原生图片、纯文本和图片请求失败。

浏览器工具按需注册，在明确浏览器任务/显式页面引用后启用；首版不新增一套插件安装流程。既有 Linux 全桌面 Computer Use 保持独立，本文不修改其审批规则。

权限分三层：

1. 目标范围：任务 + 标签页 + URL origin（协议、主机、端口）+ 允许动作类别。已有授权复用；不因页面里出现一句话就扩大范围。内网和 localhost 保持现有可访问规则，仍受本任务授权约束。
2. 常规操作：授权范围内阅读、导航、滚动、普通查询和非敏感填写可连续执行，遵循用户现有审批模式。`deny-changes` 不能被浏览器工具绕过。
3. 有实际外部后果的提交、发送、删除、权限修改、敏感信息传输等，需要与具体目标和内容绑定的有效授权；没有明确授权时才确认，不重复索取已经有效的许可。

风险判断不能只靠按钮文本，也不能接受模型自报 `risk: low`。结合动作、来源站点、目标上下文、数据类型和现有任务授权，判断不明确时暂停。Enter、快捷键、坐标点击、上传以及旧工具别名均走同一检查，不能借动作形式绕过。

审批等待期间页面可能变化；批准后重检目标、授权范围和观察代次。动作内容变化则原授权无效。受控子页跨 origin 导航、新标签页、弹窗也要重新核对范围，不能只检查初次打开网址。

网页与截图内容是不可信资料，不可提升为系统指令。远程页面不能访问主进程控制接口；维持 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。不得为实现控制新增 `--no-sandbox` 或关闭全局证书校验。

## 9. 标签页、登录、弹窗和文件

- 现有 `persist:dyworker-browser` 继续承载用户浏览器登录状态；首版不自动迁移或导出凭据。它是共享持久分区，不等于任务数据隔离，必须配合窗口级单一控制权和任务标签绑定。
- 只有任务可访问标签页能被工具列出/操作；模型切换标签页先使之可见并等 renderer 确认，用户手动切换则暂停。切换任务使旧运行失去控制权。
- 普通 GET 链接的新页可创建受控标签；不能把所有 `window.open` 都简单转成 `loadURL`。涉及 POST、opener、SSO 弹窗的流程需要保留浏览器语义或人工完成，不能为了标签显示破坏登录流程。
- JS alert/confirm/prompt 由宿主呈现并带目标来源；模态对话框期间暂停其他动作。确认框若对应敏感提交仍走授权；系统级对话框交给人工。
- 密码、短信码、扫码、验证码默认人工接管。浏览器自有保存密码功能可保持，但不把密码交给模型，不新增绕过验证码能力。
- 下载归属由唯一下载管理器记录 `controlSessionId/tabId/downloadId`，统一保存在当前工作区“下载”；路径规范化、符号链接越界、同名文件、取消/断点、零字节和错误响应均需处理。完成事件及实际文件共同验证，不在开始下载时就宣布成功。
- 多个标签页共享 session 时，只保存本任务发起且已登记的下载；旧任务清理不得删掉其他任务监听或文件。后台延迟下载若归属不明则人工确认。
- 后续上传阶段限定用户已提供/授权的具体工作区文件，校验真实路径与目标站点，利用浏览器文件控件完成，不自动操作系统选文件窗口。上传可能在选择文件时立即外发，授权检查必须先于选择动作。

## 10. 麒麟兼容策略

主路线操作 Electron 自带 Chromium 的网页内容，不依赖 xdotool、wmctrl、AT-SPI、xclip、屏幕录制或远程桌面授权。这是技术设计上的减依赖，不是麒麟兼容已经通过的证明。

| 环境 | 交付要求 |
| --- | --- |
| 麒麟 V10 ARM64 + X11 | 首要必测环境：打包安装、启动、中文、截图、输入、接管、文件 |
| 麒麟 V10 ARM64 + Wayland 桌面 + XWayland | 若目标设备使用该组合，必测现有重启兼容路径及输入；单列结果 |
| 麒麟 x86_64 | 复用实现；单独构建/验收，不将 ARM64 包称为可安装 |
| 原生 Wayland、无 XWayland | 探测启动和输入；未验证或宿主不能启动则明确不支持该组合，不假装降级成功 |
| LoongArch | 本轮不承诺；Electron 对应架构发行包与原生依赖需独立立项 |

实施者先采集实际系统版本、架构、UKUI/桌面会话、DISPLAY/WAYLAND_DISPLAY、缩放、GPU、Electron/Chromium 版本，再写兼容结论。不要只记录“Linux”。

保留当前 Linux 关闭硬件加速的逻辑；本任务不顺带全局开启。软件渲染下测截图和交互性能。中文自动输入优先 Chromium 文本输入路径；手动输入还需验证实际系统输入法及组合态，不能只验证直接赋值。

发布包只携带必要运行模块，不能在用户首次操作时联网下载浏览器。离线/内网机器可以用现有可访问的模型服务，页面截图和文字不得静默转发到其他视觉服务。纯本地测试成功不能证明远端模型、内网站点证书和政务 SSO 可用。

## 12. 实施顺序与阶段退出条件

### P0：验证底座，可行性门槛

在现有 Electron 版本做小型真实网页验证：绑定准确 webContents；读取当前页；截图回到模型；协议点击/中文输入；宿主接管；断开恢复。必须覆盖目标麒麟软件渲染与现有 XWayland 路径。在获得麒麟设备前可完成本地工程，但该阶段的麒麟门槛保持“待验证”。

退出条件：输入命中正确页面、截图非空、中文正确、接管后无新增输入。若原容器阻挡浮层或协议动作不可用，先解决适配层，不进入界面美化。

### P1：最小完整闭环

实施控制权管理、任务绑定、观察编号、语义点击/输入/滚动、截图反馈、等待、授权、接管和继续。完成“打开本地表单 → 输入中文 → 查询 → 核对结果 → 人工接管修改 → 继续”。同时封堵缓存页和后台任务误用路径。

退出条件：既有浏览器功能保持；所有动作经管理器；旧工具不绕过；任何接管竞态均不串页或继续输入。

### P2：首版能力完整

增加视觉坐标、双击/悬停/拖动、选择、iframe、受控新页、下载、弹窗、图像能力降级和崩溃恢复。完成 UI 深浅色与窄面板检查。

退出条件：第 13 节首版必测项全部通过，包括真实模型闭环及麒麟验收。P1 只能称最小可用版本，不能把未完成的视觉/复杂页能力描述成已交付。

### P3：后续扩展

文件上传、复杂 SSO 弹窗、必要时 WebContentsView 迁移、外部浏览器适配和独立浏览器账户。全桌面跨应用能力另行规划，不作为首版隐式降级。

## 13. 验收计划

先用确定性测试验证权限和竞态，再在真实 Electron 操作页面；最后用实际配置模型完成任务。纯网页预览不能证明 Electron guest、调试通道、接管、下载和系统输入法正确。

| 场景 | 预期结果 |
| --- | --- |
| 基础页面与中文查询 | 回传当前页截图/状态；中文含标点不丢字；查询结果与输入一致 |
| 大量/动态控件 | 可找到第 60 个以后的目标；重绘后旧引用拒绝，不误点第一个元素 |
| React 表单、select、contenteditable | 值与页面状态真实更新，校验提示正确 |
| 同源/跨域 iframe、开放 Shadow DOM | 命中正确 frame/control，失效能恢复，不能读取其他任务页面 |
| 画布、自定义控件、拖动、嵌套滚动 | 使用真实截图定位，动作后有可核对结果 |
| 缩放 80/100/125/150%，系统缩放 100/150/200% | 坐标命中一致；截图/视口变化后旧动作被拒绝 |
| 面板约 360/640/960px、设备模拟 | 接管始终可见，网页底部按钮无遮挡，布局变化不误点 |
| 执行中点击接管、等待中接管、审批后接管 | 主进程确认后无新输入；迟到动作不执行；可人工修改后续跑 |
| 拖动/组合键中接管 | 及时释放已按下输入，无拖拽或修饰键残留 |
| 切标签、折叠面板、切任务、双任务竞争 | 原控制暂停；不得操作缓存页、隐藏页或另一任务 |
| 网页指令诱导、越权 origin、Enter 提交 | 不扩大授权；敏感动作和快捷键不绕过审批 |
| 表单提交后响应丢失/模型重试 | 先查询业务结果；服务端计数确认没有重复提交 |
| 新页/JS 弹窗/登录验证码 | 页面归属明确；不支持路径转人工，继续前重新观察 |
| 下载同名文件/中断/退出任务 | 文件不覆盖、不越界；下载结果和真实文件一致；无重复监听 |
| 模型超时/断网/图片拒绝/不支持视觉 | 清楚暂停或文字降级，不能盲点，已完成操作不重放 |
| 打开 DevTools/guest 崩溃/调试断开/应用重启 | 暂停清理；不偷偷重新获取控制；重启不自动恢复输入 |
| 原浏览器回归 | 登录、地址建议、历史、下载、密码提示、清理确认、缩放、切页保持 |
| 麒麟安装包与手动中文输入法 | deb/AppImage 分别检查安装启动与必要依赖；组合输入正常 |

建议性能门槛（待实测校准）：接管状态反馈 p95 不超过 200ms，撤销后不再派发新输入；本地简单页观察 p95 不超过 1 秒（不含模型网络）；连续运行 30 分钟无失控循环或持续资源增长。响应超时必须暂停而不是堆积队列。

选 10 个有明确最终结果的代表任务，每个重复 5 次：中文查询、表单校验、长页筛选、下拉/复选、iframe 流程、画布/拖动、多标签资料查询、下载核验、人工接管续跑、失败恢复。全部确定性控制/权限用例必须通过；真实模型任务目标完成率至少 90%，安全误操作、串页和重复提交为 0。记录模型/服务、平均耗时、主动接管次数与失败原因，不用成功率掩盖安全失败。

node --test tests/security-approval.test.mjs tests/desktop-contract.test.mjs tests/linux-window-input.test.mjs
