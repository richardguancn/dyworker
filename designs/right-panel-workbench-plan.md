# 右面板工作台改造计划（对照 DSH-better-sidebar）

状态：草案（待确认后实施）
日期：2026-08-14
范围：仅 DYWorker 桌面端（electron/ 与 src/ 渲染端），不涉及其他项目
关联：后台任务页与 `designs/trace-console-plan.md` 共用同一条统一事件流

## 1. 结论

方向成立：我们的右面板现在是「查看器」，对方是「工作台」。差距已经逐项核对到代码，核心不是美观，而是缺少编辑、终端、Git 操作、后台任务拓扑、布局持久化这几类「能干活」的能力。

学习边界：对方是跑在 DeepSeek Harness 网页里的插件，我们是 Electron 桌面应用，原生能力比它强。它的浏览器沙箱 iframe、WebSocket 终端等是网页环境的补偿手段，我们不需要照搬；但它的产品形态（文件树 + 编辑预览 + 终端 + Git + 后台任务 + 分栏持久化）值得完整借鉴。

## 2. 两边对照

| 维度 | DSH-better-sidebar | DYWorker 现状 |
| --- | --- | --- |
| 文件树 | 懒加载目录树、行尾 @文件 引用到输入框、右键复制路径 | 有目录树、筛选、拖拽文件到聊天，无行尾 @ 按钮 |
| 编辑预览 | CodeMirror 多语言高亮、Ctrl/Cmd+S 原子保存、切 Tab 不丢草稿 | 只读预览（highlight.js 代码 / Markdown），无编辑、无保存 |
| 富媒体预览 | 图片 / HTML 沙箱 / PDF / Word / Excel / PPT 内联预览，重依赖懒加载 | 仅文本与 Markdown；图片、Office、PDF 交给系统默认应用 |
| 浏览器 | 多开、沙箱 iframe、外链默认侧边栏打开 | 原生 webview 多 Tab、后退/刷新、登录态导入，能力更强 |
| 终端 | xterm + node-pty 真实 shell、Tab 保活回放、可选注入 terminal_* 工具 | 无 |
| Git | 真 diff、懒加载历史、右键暂存/放弃/提交/还原/捡取 | 只有只读 diff 审阅（HEAD/upstream 基线切换）；commit/push/branch 的底层能力已接通 API，但面板没暴露 |
| 后台任务页 | 主会话 agent 拓扑、点击直达执行记录、子代理自动展开、后台任务实时输出 + 强制终止 | 无专门页面；队列与子代理事件已有，但没有拓扑视图 |
| 分栏与布局 | Tab 拖拽拆分/合并、底部第二面板、分隔线调比例、两面板拐角双向拖动 | 单一面板、固定 Tab，无拖拽/分栏/底部面板 |
| 状态持久化 | 布局/分栏/Tab/两面板状态按会话持久化并净化陈旧状态 | 面板状态是全局内存，切换会话不隔离、重启即丢 |

## 3. 已有的资产（不重复建设）

- 文件树：目录树 + 筛选 + 刷新 + 拖拽引用到输入框 + 移除工作目录。
- 预览：代码高亮、Markdown 渲染、二进制交给系统应用。
- Git：完整 CLI 封装已存在（commit / push / checkout / create-branch / diff / review），preload 已暴露；只差面板上的写操作入口与暂存/放弃等辅助动作。
- 浏览器：原生 webview 多 Tab、Cookie/登录态导入注入，比对方沙箱更强。
- 侧边聊天、审批收件箱、队列与子代理事件、活动/计划/文件变更流。

## 4. 分阶段方案

### Phase 1 补「工作台」核心（见效最快）

1. 文件编辑与保存：只读预览升级为可编辑，Ctrl/Cmd+S 保存；新增 `workspace:write-file` IPC，只允许写会话工作目录内文件，原子写入、保留编码、写前校验；未保存草稿在切 Tab 时保留并提示。
2. 文件引用：文件树行尾加「@引用」按钮，把文件引用到输入框（已有拖拽引用，补齐显式入口）。
3. Git 操作：面板接入已有的 commit / push / checkout / create-branch，并补右键暂存、放弃、还原；push 与放弃这类不可逆操作仍走人工确认（对齐现有审批语义）；提交信息按既有规则生成。
4. 布局持久化：面板 Tab、分栏比例按会话持久化到本地存储，切换会话恢复，重启不丢；清理陈旧会话状态。

### Phase 2 工作台能力

5. 终端：引入真实 shell（node-pty + xterm），每会话上限、Tab 保活与重连回放；可选为模型注入 terminal_* 工具（默认关）。
6. 后台任务页：主会话 agent 拓扑（复用 dispatch_agent 子代理事件与队列），点击直达执行记录、新子代理自动展开；后台任务显示类型徽标与退出码、实时输出非消费式查看、两击确认强制终止（对齐现有取消语义）。

### Phase 3 按需增强（低优先级）

7. 预览扩充：先做图片与 HTML（沙箱 iframe）内联预览，再做 PDF，Office（Word/Excel/PPT）依赖重、放最后且按需懒加载。
8. Tab 拖拽、分栏拆分、底部第二面板：UI 复杂度高、回归风险大，等前两阶段稳定后再评估。

## 5. 不照搬的部分

- 浏览器沙箱 iframe：Electron 原生 webview 与现有权限处理已覆盖，不强套它的网页沙箱模型。
- 插件注册服务与声明式设置：暂不对外做插件机制；内部先抽象 Tab 注册表，方便后续扩展。
- 移动端断点：DYWorker 是桌面应用，不做它的移动端抽屉逻辑。

## 6. 风险与取舍

- 写文件安全：只允许会话工作目录内路径，原子写，拒绝二进制/超大文件直接覆盖。
- Git 破坏性动作：push、放弃、还原走人工确认或二次确认，不静默执行。
- 终端资源：node-pty 有原生二进制，三平台行为不同（Windows 缺编译产物需工具链）；先限 macOS/Linux 验证，Windows 标注未验证。
- 性能：文件树与终端按需加载，预览器懒加载，面板状态持久化做上限与陈旧清理。
- 兼容与共存：改动在现有未提交改动基础上窄改；老数据无布局状态时用默认布局。

## 7. 验收清单（DoD）

- 文件可编辑并保存（含未保存草稿提示与原子写），引用按钮与拖拽引用都可用；
- Git 暂存/放弃/提交/分支/推送在真实仓库走通，破坏性动作有确认；
- 终端可开、可执行、断开重连可回放，会话隔离正确；
- 后台任务页能看到主会话与子代理拓扑，点击直达、实时输出、强制终止可用；
- 面板布局与 Tab 状态跨会话、跨重启保持；
- `npm run verify` 全绿；macOS 本地端到端验证，Windows / Linux 标注验证边界。
