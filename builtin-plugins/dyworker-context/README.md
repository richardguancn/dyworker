# dyworker-context（上下文插件）

自研内置插件，复刻 [dsh-context](https://github.com/bowenliang123/dsh-context) 的会话内核心面：
看清「上下文窗口里装了什么、怎么长起来的、模型拿它做了什么」。

## 两个位置

| 插槽 | 标签 | 内容 |
| --- | --- | --- |
| `conversation.view` | 上下文 | 完整卡片：KPI / Token 与耗时统计 / 当前上下文构成 / **上下文浏览器** / 上下文事件 / 文件活动 / Agent 网络 / 上下文趋势 |
| `sidebar.right.pane.tab` | 上下文仪表盘 | 跨会话：区间与排序切换、每日用量、8 周活跃热力图、会话卡片（构成环，点卡片进入会话） |

右侧面板**只登记仪表盘**：会话区已经有完整的「上下文」标签，紧凑面板与它重复，已移除。
插件登记的面板标签**不自动展开右栏**、也不写进按会话保存的面板布局（宿主 `src/App.tsx` 负责），
所以内置插件不会开机抢版面。

## 三条路由（主机半边 `index.js`）

| 路由 | 入参 | 返回 |
| --- | --- | --- |
| `POST /api/dyworker-context/detail` | `{ sessionId }` | `session`（标题/工作区/模型/窗口/累计用量）+ `timeline`（contextTimeline 投影：构成、计数、每请求占用、元素清单）+ `trace`（逐请求 token、上下文事件、文件活动、工具与计时） |
| `POST /api/dyworker-context/browser` | `{ sessionId }` | 上下文元素（含正文与思考，单条截断 4000 字符）+ 按类别计数，供浏览器展开看内容 |
| `POST /api/dyworker-context/balance` | `{ days }` | 跨会话用量：连续 N 天序列、总量、会话卡片、按工作区分组；用量最大的 16 个会话带上下文构成环 |

## 数据从哪来（三处，各管一段）

1. **sessionProjections → contextTimeline**：由我们自己的会话消息折出来的真实投影，
   给「构成 / 每个请求的占用 / 元素清单」；
2. **会话的 trace 事件流**：给逐请求输入输出 token、上下文事件（压缩 / 计划 / 文件变更）、
   工具调用与耗时、文件活动；
3. **会话记录本身**：标题、工作区、模型、上下文窗口、累计用量。

## 如实标注的两处估算

- **系统提示词**：会话记录里没有它，只有请求载荷里有；载荷写日志时被截断到 12000 字符，
  所以系统提示词按请求载荷估算，历史消息按会话消息估算，两者合并后重算占比。
- **工具定义（tool schemas）**：同样被截断截掉了，界面上写「未记录」，不编数。

## 构建

与轨迹插件一致：`npm run build:plugins`（产物 `client.js`），改主机半边要重启 Electron。
