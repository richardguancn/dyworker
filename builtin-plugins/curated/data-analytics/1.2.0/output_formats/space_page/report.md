# Native Page reports

This is the ordinary workflow for a **new report using standard charts**. Read it with the report/analytical skill and selected chart family. It includes native source composition, destination, attribution and handoff; do not also load `spaces-report.md`, `report-sources.md` or the full output-format guide for these same steps. Use the exceptional paths below when needed. Preserve the user's template and section order.

## Prepare the report and evidence

Set the native Page title to the concrete subject or strongest supported finding, preserving a requested title; do not repeat it as a heading. Start with a compact preparation date/known-author byline, then follow the [report principles](../../skills/build-report/SKILL.md#report-principles) for a visible Executive Summary: usually 2–4 connected takeaways or short paragraphs linking the findings, decisive comparisons and implications, with material caveats and useful recommendations. If the reader's question is implicit, add a short opening sentence before the summary. Avoid an adjacent duplicate lede or KPI restatement. A short answer can open more briefly. Follow with findings, charts, interpretation, decision and uncertainty as appropriate. Keep units, periods, denominators and causal limits beside the affected claims. Compute derived comparisons used in prose and recommendations from the selected inputs; retain those reviewed values alongside the chart calculations so the body and sources use the same results.

Number sources by first appearance. A chart or table and adjacent prose using the same evidence share one source-subpage reference below the visual; omit duplicate inline citations in that prose. For prose-only groups, cite the first material claim. Cite again when source, population or period changes, or a separate section must stand alone. Compact comparison tables can serve the argument; raw plotted tables, SQL and reproduction details belong in sources.

Each source child has a short title such as `[1] Weekly activity` and these applicable parts:

- **Overview first:** a concise finding and visible labeled bullets for reporting/comparison period, population/filters, caveats, metric definition/denominator and source identity. Omit inapplicable labels; retain material unknowns.
- **Data:** provenance and original links, recorded retrieval/execution time and cutoff when known, grain, row/column counts, units, definitions of fields used, and complete saved inputs/results. For a large result, label a preview and link accessible complete evidence; never call a preview complete.
- **SQL query:** exact recorded SQL and available run links, engine, timing, row counts and scope. Files/documents need no invented query or empty section.
- **Evidence flow:** actual calculations, denominators, transformations, chart mappings, rounding, reconciliation and checks performed. Preserve precision. Document-only sources can use a short overview, relevant evidence, original link and freshness.

Group claims readers can verify together. Reuse canonical evidence while keeping each source understandable. A chart source repeats the reviewed chart near the top, with exact plotted values/calculations below. Add a backlink to the returned report URL. Pages supplies the source list; do not append a duplicate list.

## Create, connect and finish

1. **Destination.** For a new private personal report, omit `space_id` and `parent_page_id`. For a requested Space/parent, resolve its real ID, audience and scoped instructions before copying evidence. Use supported creation tools; missing skill discovery or failed preview does not establish creation failure. Preserve explicit formats. For conflicts/unavailable creation use [destination selection](../../shared/output-and-template-handling.md#output-format-selection).
2. **Create once.** Send complete prose/comparison sections as `initial_blocks`. Retain each creation result before displaying it; print only its Page ID, URL and status, not the full document envelope. This avoids losing the new Page's identity to output truncation. Set `namespace: "data_reports"` on the main Page and each source child when supported; it is not inherited. Add this separate first block while unfinished: `> ⏳ **Report in progress.** Data agent is working, and this Page’s content may change.` When native opening is available and the user has not requested no opening or another surface, open only the main Page in the current chat's panel by its returned ID. Queued opening is not confirmed visibility. Create source children under it in citation order and retain all IDs/URLs. Use plain citation numerals until URLs exist; never save placeholders or invented links.
3. **Charts.** Prepare the [Visualize chart fragment](../../skills/visualize-data/docs/rendering/page-chart-fragment.md) and check its reviewed values before uploading. Reuse the unchanged HTML in report and chart source. Read both targets with their guidance, then upload to the independent Pages concurrently. Keep writes within each Page sequential with its own current guards. Inspect every result, including rejected edits inside successful calls; repair only the failed destination. Use one visible chart title, meaningful labels/units and standard component appearance. Avoid redundant adjacent headings.
4. **Connect and complete in one edit.** Once source/chart saves and evidence checks pass, batch citation links, chart source links and removal of the progress block in one final non-patch edit. Use whole-block replacements for citation changes so they can share the atomic batch with insertions and deletion. In prose citations, link only the numeral. Place the “View source” link immediately below its report chart or table, in a native Page block outside the embedded HTML and before interpretation, using the corresponding returned source Page URL. Use supported positions and observed IDs/hashes; visualization and Markdown positions may differ. Keep Page identities after partial failures. If upload succeeded but insertion failed, follow recovery before reuploading. A common parent does not prove file access; upload per destination unless cross-Page reuse is explicitly supported and verified. Keep the progress notice if requested work remains unfinished.

   ```markdown
   \[[1](RETURNED_SOURCE_URL)\]

   [View source](RETURNED_SOURCE_URL)
   ```

5. **Verify saved content.** Reuse current snapshots/receipts; refresh when edits invalidate needed guards, on conflict or unknown outcomes. Batch independent reads, sharing checks and Page-scoped file reads; inspect all settled results and retain successful saves. Check quantitative claims, including supporting recommendation rationale, against the original inputs and reviewed calculations; agreement between the report and its source prose alone is insufficient. Read report and sources for scope, numeral citations/backlinks, chart references, complete evidence, destination and `data_reports` attribution. The final report read also confirms removal of the progress notice; do not add a separate cleanup write/read when that edit succeeded. Preserve audience and source access; never widen sharing to repair a reference.
6. **Deliver.** An uncertain cause belongs in findings, not an endless progress notice. Label truly unfinished work as a draft and state what remains. Before the final response, call the advertised native Page-opening action with the completed main Page's returned ID unless it is already visible or the user requested another surface/no opening. Inspect the result; queued is not confirmed open. Reuse its tab, leave the primary requested report selected and deliver its actual link with a concise finding. If opening is unavailable or fails, keep the saved Page and disclose the limitation. Do not open source children or create an HTML companion or Site publication unless requested.

Assume successfully prepared and saved **standard components render**. Content/reference checks complete ordinary authoring; no browser polling, hover/theme/width checks or image generation as a completion gate. Do not claim visual checks ran. Keep delivery uncertainty separate from analytical caveats.

## Exceptional paths

- Existing reports, refreshes or collaborator changes: [revise the same Pages](../../skills/build-report/docs/spaces-report.md#revise-and-refresh), preserving IDs, audience, source relationships and existing attribution.
- Custom charts, explicit visual review or reported failure: follow [Visualize Data’s bounded checks and fallback procedure](../../skills/visualize-data/docs/rendering/page-chart-fragment.md#custom-charts-and-fallbacks), preserving working and unverified charts.
- Selected template: read it and the [template contract](../../shared/output-and-template-handling.md#template-handling), preserving format and unsupported-style disclosures.
- Conversion/sharing: [Page export/share](../../skills/build-report/docs/spaces-report.md#export-or-share-a-page-report). A report link alone does not authorize publication.
