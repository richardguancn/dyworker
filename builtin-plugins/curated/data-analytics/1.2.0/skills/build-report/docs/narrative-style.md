# Report composition

[Data writing](../../../shared/data-writing.md) owns wording, scannable findings, numerical context, hypotheses and recommendations across surfaces. Apply the [central report principles](../SKILL.md#report-principles); use this reference only for report-specific composition.

## Opening and title

Follow the report principles for title, date, attribution and Summary. Keep workspace identity and detailed comparison setup in Sources and methods.

## Compose evidence sections for a quick scan

Give each section one main finding. A useful default is a finding heading, chart, brief interpretation and nearby source; add a table only for a distinct lookup, denominator, segment or action need. This is not a chart quota. Match the visual comparison to the section’s finding.

Put full calculations, long tables and methods in later sections or selective disclosure; never hide evidence that reverses the conclusion.

App reports can use `src/content/shared/ReportDisclosure.jsx` for optional detail. Retain normal body typography, coherent editable Markdown units and accessible sources. Do not turn every finding into an accordion or automatically open details in Edit mode. Include reader-visible detail in static exports.

## Investigations and next steps

Use [investigative reports](investigative-report.md) for a question-led investigation: connect each hypothesis to evidence and the current conclusion, then identify useful discriminating tests. [Conversion cohorts](../../visualize-data/docs/charts/funnel.md#conversion-cohorts) govern funnel comparisons. The [report skill](../SKILL.md#choose-useful-next-steps) owns next-step selection and placement; the shared writing guide owns its wording.
